# 从零搭一个推荐系统

<SeriesNav series="recsys" />

你打开 Spotify，首页给你推了一首没听过的歌。你点进去听了，还不错。然后你开始想：它怎么知道我会喜欢这首？

这个问题拆开来其实是两个问题。第一个：Spotify 曲库里有一亿首歌，它凭什么只给你看这 30 首？第二个：这 30 首里，排在第一位的那首凭什么排第一？

第一个问题叫召回，从一亿首里快速捞出几百首可能相关的。第二个问题叫排序，从几百首里精确挑出最匹配的排在最前面。

一亿首不可能逐个算一遍你喜不喜欢，时间上来不及。所以要先粗筛再精排。粗筛求快，用简单规则大量过滤。精排求准，用更多信号精确打分。

这篇记录的就是从零搭一套这样的流水线的过程。数据用的 MovieLens，技术用的 Python + FastAPI。

## 问题

推荐系统要做的事情：

```text
给用户 u，在所有物品 i 中，找到得分最高的 Top K
score(user, item) → 排序 → Top K
```

物品数量一大，逐个算分就来不及了。工业界的做法是分两步，先用简单规则快速筛出几百个候选（召回），再对这几百个用更复杂的方式精确打分（排序）。

## 召回：三路并行

召回的目标是从全量物品里快速捞出一批候选。一种策略总有覆盖不到的地方，所以跑了三路：

```text
多路召回（各取 40 部候选）
  ├─ 热门召回        → 评分人数多 + 均分高的电影
  ├─ 类型偏好召回    → 用户常看类型的高分电影
  └─ ItemCF 召回    → 协同过滤相似电影
```

### 热门召回

找评分人数多、均分高的电影。不依赖用户历史，新用户也能用。

### 类型偏好召回

统计用户看过的电影类型分布，按频率算权重。看了 7 部 Drama、3 部 Comedy，那 Drama 权重 0.7、Comedy 权重 0.3。从对应类型里按权重选高分电影。

### ItemCF 召回

思路是：

```text
喜欢 A 的人也喜欢 B → A 和 B 相似 → 用户看过 A，推荐 B
```

离线扫一遍所有用户行为，统计物品之间的共现关系，算出每个物品的相似物品列表。在线时只查表。

有一个细节。活跃用户看过几百部电影，不加处理会让所有物品两两相似。所以要用 IUF 加权，看得越多的用户，每次共现贡献越低：

```text
weight = 1 / log(1 + 用户看过的电影数)
```

和搜索引擎的 IDF 一个道理。

## 合并：归一化

三路召回各自返回候选和分数，但分数尺度完全不同：

```text
热门召回：recall_score = 评分人数（几十到几千）
类型召回：recall_score = 类型权重 × 均分（0 到 10）
ItemCF：  recall_score = 相似度累加（0 到 几）
```

直接加起来没意义。先归一化到 [0, 1]：

```text
normalized = (score - min) / (max - min)
```

然后按权重合并：

```text
merged_score = 0.5 × itemcf_norm + 0.3 × genre_norm + 0.2 × popular_norm
```

ItemCF 最个性化给了最高权重，热门最泛化权重最低。合并之后去掉用户已看过的电影，输出候选集。

---

## 排序：加物品质量信号

召回阶段只管"这部电影和用户有没有关系"，没管电影本身好不好。一部匹配口味但只有 3 分的烂片不应该排前面。排序阶段把物品质量信号加进来：

```text
final_score = 0.5 × recall_score_norm    （召回置信度）
            + 0.3 × avg_rating_norm      （用户评分质量）
            + 0.2 × popularity_norm      （多少人看过）
```

跑出来看效果：

| 电影 | 召回排名 | 精排后 | 原因 |
|------|---------|--------|------|
| Raiders of the Lost Ark | 1 | 2 | 召回分最高，但质量信号不如肖申克 |
| Shawshank Redemption | 2 | 1 | 评分 9.1 + 310 万人评 |
| Godfather: Part II | 未进前 5 | 5 | 评分 8.7 + 210 万人评，热度补位 |

## 代码结构

```text
recommender/
  loader.py       # 数据加载，统一 ID 类型
  recall.py       # 三路召回 + 归一化合并
  ranker.py       # 精排打分
main.py           # FastAPI，对外暴露 /recommendations
scripts/
  build_itemcf.py # 离线构建 ItemCF 相似表
```

最终接口：

```text
GET /recommendations?user_id=1&top_k=20

→ 内部流程：
  popular_recall(40) ─┐
  genre_recall(40)   ─┼→ 归一化合并(50) → rank_candidates → Top 20
  itemcf_recall(40)  ─┘
```

## 和工业界的距离

| 环节 | 这个项目 | 工业界 |
|------|---------|--------|
| 数据 | MovieLens pkl 文件 | 数据仓库 + 实时日志流 |
| 召回 | popular + genre + ItemCF | 同 + 向量召回 + DNN 召回 |
| 排序 | 手写线性公式 | DeepFM / DIN / Wide&Deep |
| 服务 | FastAPI + pandas 内存 | gRPC + Redis + 微服务 |

区别在规模和精度，结构一样。
