# 推荐系统 × 大模型：四层重叠与五大范式

<SeriesNav series="recsys" />

做完推荐系统和大模型两条线之后，最大的感受是：这两个领域不是平行的，而是深度交织的。

重叠分四层，深度递进：

1. **完全共享**（同一技术） — Transformer、Embedding、Faiss/HNSW、知识蒸馏。两边在用完全相同的代码库，只是输入数据不同。
2. **范式共享**（同一思路） — 序列建模最典型：SASRec 和 GPT 本质上是同一个 Causal Transformer，一个预测下一个 item，一个预测下一个 token。MoE 也是——MMoE 的多门控结构比 Mixtral 早出现好几年。
3. **目标共享**（优化同类问题） — RLHF 的 reward model 和推荐系统的点击率模型结构几乎一样，都是"预测人类偏好"。Scaling Laws 是核心议题：LLM 的幂律规律在推荐系统里是否成立？
4. **LLM→推荐直接融合**（最前沿） — 单向流动。LLM 的能力（世界知识、语义理解、Zero-shot 泛化）正在被注入推荐系统，尤其是冷启动和语义召回场景。

## 核心矛盾：ID vs Text

整个领域的核心矛盾只有一个：**ID vs Text**。

传统推荐靠协同过滤 ID——`item_3721` 本身没有语义，但从用户行为中学到的 Embedding 知道"买了 A 的人也买了 B"。LLM 靠文本——知道"《指环王》是奇幻史诗电影"，但完全不知道谁看过它。

五个范式是解决这个矛盾的五种姿势，最重要的分水岭在第④层。

---

## 语义 ID 为什么是真正的突破

前三种方法都在回避矛盾：要么完全放弃 CF 信号（①），要么把 LLM 当黑盒编码器（②），要么用无意义的 ID 字符串凑合（③）。

**TIGER**（2023 年 Google）第一次系统性地解决了这个问题。核心思路是把物品量化成 LLM 能理解的离散 token：

```text
物品描述文本
    ↓ BERT 编码
连续向量 [0.2, -0.8, 0.4, ...]
    ↓ RQ-VAE（残差向量量化）
离散 token 序列 [42, 7, 156]   ← 这就是"语义 ID"
    ↓ 加入 LLM 词表
像普通词一样被 LLM 处理
```

量化的关键性质：

- 语义相近的物品，生成的 token 序列**前缀相同**（层次化聚类）
- 训练时可加入协同过滤损失，让 token 同时捕获行为相似性
- LLM 可以"生成"从未出现过的物品 token，天然处理冷启动

## 工业落地的现实困境

即便是最成熟的 ④，目前离大规模工业落地还有距离：

| 问题 | 原因 | 现有缓解方案 |
|------|------|-------------|
| 推理延迟 | 自回归生成逐 token 输出 | 提前算好 Embedding，只在精排用 |
| 物品规模 | 百万物品 token 数爆炸 | RQ-VAE 分层量化压缩 |
| 更新频率 | 新物品需重新量化 | 增量量化 + 语义泛化 |
| 训练成本 | LLM 微调极贵 | LoRA + 冻结底层 |

这也是为什么 Meta 的 **HSTU** 选择了不同路线——不是让 LLM 生成推荐结果，而是把 Transformer 架构直接嵌入推荐系统的召回/排序链路，用工程换来可落地性。这正是第 ⑤ 层在探索的方向。

## 对我的意义

做推荐系统的人学 LLM 不是转行，是在**同一条路的更高层**继续走。反过来也成立。两个领域的技术债可以互相还。

具体地说：
- 推荐系统的**工程能力**（低延迟、大规模、多目标优化）是 LLM 落地最缺的
- LLM 的**语义理解**和**泛化能力**是推荐系统冷启动最需要的
- 第 ⑤ 层"统一 Backbone"是两条线的终极交汇点
