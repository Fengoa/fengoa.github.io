# 给推荐系统加上向量召回

有一种推荐你能理解，有一种你理解不了。

能理解的那种：你看了三部诺兰的电影，系统推第四部诺兰的电影。逻辑清晰，你看过的和推给你的之间有明确的共同标签。

理解不了的那种：你看了《肖申克的救赎》和《辛德勒的名单》，系统推了一部你没听过的 90 年代独立电影。你点进去看了，确实喜欢。但你说不清它跟前两部有什么关系，不是同一个导演，不是同一个类型标签，演员也没有重合。

第一种是类型匹配，规则能写出来。第二种不一样，系统不是在看标签，是在看某种更深的东西。两部电影可能从来没有被同一个人同时评过高分（所以协同过滤也发现不了），但系统认为它们是一类东西。

向量召回做的就是这件事。它把每部电影压缩成一串数字，用数字之间的距离来衡量像不像。这种相似度不依赖任何显式标签或共现记录，是从整体评分模式里学出来的隐含关系。

---

## 从评分矩阵到向量

起点是一张大表。6040 个用户 × 3706 部电影，一百万条评分，95% 的格子是空的。

```text
         电影1  电影2  电影3  ...  电影3706
用户1     9      -      8         -
用户2     -      7      -         6
用户3     8      -      9         -
...
用户6040  -      -      -         7
```

矩阵分解（SVD）把这张稀疏大表拆成两张小表，让它们乘回去之后尽量接近原表。

```text
R (6040 × 3706) ≈ U (6040 × 64) × V^T (64 × 3706)

 用户对电影的评分      用户的"口味卡"     电影的"特征卡"
（大部分是空的）     （每人 64 个数字） （每部 64 个数字）
```

U 矩阵里，每个用户被压缩成 64 个数字，描述口味偏好。V^T 矩阵里，每部电影也是 64 个数字，描述特征。两个向量做内积就是预测评分，口味和特征越匹配内积越大。

原来 95% 的格子是空的，但拆分之后任意用户和任意电影都有了向量，都能算内积。等于用已知的 5% 推断了其余 95% 的潜在偏好。

64 这个维度是人为选的，越大拟合越精确但越慢。训练一百万条数据，0.2 秒跑完。

## 验证：向量学到了什么

拿几部电影的向量算余弦相似度，看最近邻是谁：

```text
【Toy Story】→ Toy Story 2 (0.81), Bug's Life (0.55), Aladdin (0.43)
【Star Wars IV】→ Empire Strikes Back (0.70), Return of Jedi (0.53), E.T. (0.32)
【Shawshank】→ Good Will Hunting (0.51), Schindler's List (0.37), One Flew Over Cuckoo's Nest (0.37)
```

动画片聚一起，科幻冒险聚一起，深沉人性片聚一起。

E.T. 和 Star Wars 这两部，被同一个人同时高评的次数不一定很多，ItemCF 可能发现不了它们的关系。但向量认为它们在"家庭+科幻+冒险感"这些隐含维度上接近。

## FAISS：向量多了怎么搜

有了向量之后，问题就是给一个用户向量，从 3706 个电影向量里找最近的 40 个。

3706 个暴力搜就行，零点几毫秒。物品量到千万级就需要索引了。FAISS（Facebook 开源的向量检索库）预先把向量按空间位置分组，搜索时只查最可能的几个组。这个项目因为只有 3706 部电影，直接暴力搜。将来数据量大了换一行代码改索引类型，接口不变。

```text
用户向量 (64个数字) → FAISS 索引（存着 3706 个电影向量）→ 最近的 40 部 + 相似度分数
```

## 接入流水线

向量召回作为第四路接入，各自出候选，归一化到 [0,1]，加权合并：

```text
popular_recall    (权重 0.15) ─┐
genre_recall      (权重 0.20) ─┤
itemcf_recall     (权重 0.35) ─┼→ 归一化合并 → 精排 → Top K
vector_recall     (权重 0.30) ─┘
```

ItemCF 给了最高权重因为共现信号最直接。向量次之，补充覆盖不到的语义关系。

拿用户 1 测试：

```text
V1（3路）：Shawshank 被 itemcf+popular 命中
V2（4路）：Shawshank 被 itemcf+popular+vector 三路命中，分数更高

V1：Fantasia 没出现
V2：Fantasia 被 genre+itemcf+vector 三路命中，进了推荐列表
```

向量召回把一些"语义上应该推但没有共现证据"的电影拉了进来。

## 离线流程

```bash
# 训练 Embedding（矩阵分解，0.2 秒）
uv run python scripts/build_embeddings.py

# 构建 FAISS 索引
uv run python scripts/build_faiss_index.py
```

产出：

```text
data/processed/
  movie_embeddings.npy    # 3706 × 64，每部电影一个向量
  user_embeddings.npy     # 6040 × 64，每个用户一个向量
  faiss_index.bin         # FAISS 索引文件
  movie_id_index.pkl      # movie_id → 向量行号
  user_id_index.pkl       # user_id → 向量行号
```

## 和工业界的距离

| 环节 | 这个项目 | 工业界 |
|---|---|---|
| Embedding 训练 | SVD 矩阵分解 | 双塔模型 / DSSM / YouTube DNN |
| 向量维度 | 64 | 128-256 |
| 索引类型 | FlatIP（暴力精确搜索） | IVF / HNSW（近似搜索，百万级毫秒返回） |
| 更新频率 | 手动重跑脚本 | 每日/实时增量更新 |

工业界的 Embedding 用神经网络训练，能加入更多特征。索引用近似算法扛更大量级。
