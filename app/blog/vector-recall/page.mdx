# 给推荐系统加上向量召回

有一种推荐你能理解，有一种你理解不了。

能理解的那种：你看了三部诺兰的电影，系统推第四部诺兰的电影。逻辑清晰——你看过的和推给你的之间有明确的共同标签。

理解不了的那种：你看了《肖申克的救赎》和《辛德勒的名单》，系统推了一部你没听过的 90 年代独立电影。你点进去看了，确实喜欢。但你说不清它跟前两部有什么关系——不是同一个导演，不是同一个类型标签，演员也没有重合。

第一种叫类型匹配，规则能写出来。第二种是另一回事——系统不是在看标签，是在看某种更深的东西。两部电影可能从来没有被同一个人同时评过高分（所以协同过滤也发现不了它们的关系），但系统认为它们"是一类东西"。

这就是向量召回在做的事。它把每部电影压缩成一串数字（向量），用数字之间的距离来衡量"像不像"。这种相似度不依赖任何显式标签或共现记录——它是从整体评分模式里学出来的隐含关系。

下面是具体怎么做的。

---

## 从评分矩阵到向量

起点是一张巨大的表：6040 个用户 × 3706 部电影，一百万条评分。95% 的格子是空的。

```text
         电影1  电影2  电影3  ...  电影3706
用户1     9      -      8         -
用户2     -      7      -         6
用户3     8      -      9         -
...
用户6040  -      -      -         7
```

矩阵分解（SVD）做的事：把这张稀疏大表拆成两张小表，让它们乘回去之后尽量接近原来的大表。

```text
R (6040 × 3706) ≈ U (6040 × 64) × V^T (64 × 3706)

 用户对电影的评分      用户的"口味卡"     电影的"特征卡"
（大部分是空的）     （每人 64 个数字） （每部 64 个数字）
```

怎么理解这个拆分：

- **U** 矩阵：每个用户被压缩成 64 个数字。这 64 个数字描述了用户的口味偏好。比如某一维可能代表"喜不喜欢深沉的东西"，另一维可能代表"对快节奏有没有偏好"。具体含义不是人为定义的，是算法自己从评分数据里学出来的。

- **V^T** 矩阵：每部电影也被压缩成 64 个数字。同样的 64 个维度，描述这部电影在各个方面的特征。

- **为什么乘回去能还原评分**：用户的"口味卡"和电影的"特征卡"做内积（对应位置相乘再加起来），得到的数字就是"预测这个用户给这部电影打多少分"。口味和特征越匹配，内积越大，预测分越高。

- **为什么空格也能填上**：原来大表 95% 是空白的，但拆分之后，任意一个用户和任意一部电影都有了向量，都可以算内积。等于用已知的 5% 评分推断出了其余 95% 的潜在偏好。

- **64 这个数字哪来的**：人为选的。越大拟合越精确但越慢，64 是一个常见的平衡点。

训练一百万条数据，0.2 秒跑完。

---

## 验证：向量真的学到了语义吗

训练完之后，拿几部电影的向量算余弦相似度（方向越接近值越大，满分 1.0），看离它最近的是谁：

```text
【Toy Story】→ Toy Story 2 (0.81), Bug's Life (0.55), Aladdin (0.43)
【Star Wars IV】→ Empire Strikes Back (0.70), Return of Jedi (0.53), E.T. (0.32)
【Shawshank】→ Good Will Hunting (0.51), Schindler's List (0.37), One Flew Over Cuckoo's Nest (0.37)
```

动画片聚在一起，科幻冒险聚在一起，深沉人性片聚在一起。

注意 E.T. 和 Star Wars——这两部电影被同一个人同时喜欢的次数未必很多（ItemCF 可能捕捉不到），但向量认为它们在"家庭+科幻+冒险感"这些隐含维度上接近。这就是向量比共现统计多看到的东西。

## FAISS：向量多了之后怎么快速搜

有了向量之后，问题变成：给定一个用户向量，从 3706 个电影向量里找最近的 40 个。

3706 个，逐个算距离也就零点几毫秒，暴力搜就行。但如果是淘宝那种 4000 万件商品呢？逐个算距离要好几秒，用户等不了。

FAISS（Facebook 开源的向量检索库）解决这个问题。思路类似于图书馆的索引卡片——不用把每本书翻一遍，先按分类缩小范围，再在小范围里精确搜。FAISS 预先把向量按空间位置分组建索引，搜索时只查最可能的几个组，速度从"遍历全部"变成"查一小撮"。

这个项目里因为只有 3706 部电影，用的是最简单的暴力精确搜索。但如果将来物品量到百万级，只需要换一行代码把索引类型改成 IVF 或 HNSW，接口完全不变。

```text
用户向量 (64个数字) → FAISS 索引（存着 3706 个电影向量）→ 最近的 40 部 + 相似度分数
```

## 接入现有流水线

向量召回作为第四路，接入之前已有的多路合并。和前三路完全平等——各自出候选，归一化到 [0,1]，加权合并：

```text
popular_recall    (权重 0.15) ─┐
genre_recall      (权重 0.20) ─┤
itemcf_recall     (权重 0.35) ─┼→ 归一化合并 → 精排 → Top K
vector_recall     (权重 0.30) ─┘
```

权重分配的逻辑：ItemCF 仍然最高，因为"被同一个人同时喜欢过"是最直接的信号。向量次之，它补充 ItemCF 覆盖不到的语义关系。Genre 和 popular 作为兜底和多样性补充。

实际效果，拿用户 1 测试：

```text
V1（3路）：Shawshank 被 itemcf+popular 命中
V2（4路）：Shawshank 被 itemcf+popular+vector 三路命中，分数更高

V1：Fantasia 没出现
V2：Fantasia 被 genre+itemcf+vector 三路命中，进了推荐列表
```

向量召回的独有贡献：把一些"语义上应该推但没有共现证据"的电影拉了进来。

## 离线流程

```bash
# 训练 Embedding（矩阵分解，0.2 秒）
uv run python scripts/build_embeddings.py

# 构建 FAISS 索引
uv run python scripts/build_faiss_index.py
```

产出：

```text
data/processed/
  movie_embeddings.npy    # 3706 × 64，每部电影一个向量
  user_embeddings.npy     # 6040 × 64，每个用户一个向量
  faiss_index.bin         # FAISS 索引文件
  movie_id_index.pkl      # movie_id → 向量行号
  user_id_index.pkl       # user_id → 向量行号
```

## 和工业界的距离

| 环节 | 这个项目 | 工业界 |
|---|---|---|
| Embedding 训练 | SVD 矩阵分解 | 双塔模型 / DSSM / YouTube DNN |
| 向量维度 | 64 | 128-256 |
| 索引类型 | FlatIP（暴力精确搜索） | IVF / HNSW（近似搜索，百万级毫秒返回） |
| 更新频率 | 手动重跑脚本 | 每日/实时增量更新 |
| 向量库 | FAISS 本地文件 | Milvus / Pinecone / Qdrant |

结构一样，差距在于：工业界的 Embedding 用神经网络学得更好（能加入更多特征），索引用近似算法扛住更大量级。
