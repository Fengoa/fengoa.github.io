# Scaling Law：更大一定更好吗

<SeriesNav series="llm" />

上一篇训练了 4M 参数模型，过拟合明显——参数约为 token 数的 15 倍。需缩小模型或扩充数据，但具体比例难以凭直觉确定。

2020 年 OpenAI 的 Kaplan 论文提出了一组幂律：模型 loss 和参数量、数据量、算力之间，分别都遵循一条直线（在 log-log 坐标上）。2022 年 DeepMind 的 Chinchilla 修正了 Kaplan 的结论，给出了一个更尖锐的版本：

<Math block>{`\\text{固定算力 } C \\text{ 时，最优配比} \\quad \\frac{D}{N} \\approx 20`}</Math>

也就是说，每个参数大约应该消化 20 个 token。这一篇用一组 mini 实验把幂律和最优点都摸一遍，再回头解释为什么 GPT-3 那个时代的模型几乎人人都“参数太多、数据太少”。

## 实验装置

字符级 Tiny Shakespeare（约 100 万 token），模型从 53K 扫到 10.7M 参数。三组实验全部走同一份训练 loop，只换三件事中的一件：模型大小、数据量、固定算力下的 N/D 配比。

下面这张图把三组数据合并到一处，用 tab 切换横轴。每个 tab 都是一条 log-log 直线——这就是幂律。

<ScalingLawLoglogPlot />

参数量从 53K 涨至 3.2M（60×），val loss 从 2.07 降至 1.51。xlarge（10.7M）反而劣于 large：100 万 token 无法支撑 1000 万参数，模型开始记忆训练集。该反弹点即 Chinchilla 论文强调的——给定数据量，存在最优模型规模，超出后性能退化。

数据量这边趋势更干净：从 5% 到 100% 数据，loss 从 2.70 一路降到 1.76，5%→20% 段最陡，之后边际递减。算力曲线则把 N 和 D 一起扩，所以斜率介于两者之间。

把三条曲线写成统一形式：

<Math block>{`L(N) = \\Big(\\dfrac{N_c}{N}\\Big)^{\\alpha_N},\\quad L(D) = \\Big(\\dfrac{D_c}{D}\\Big)^{\\alpha_D},\\quad L(C) = \\Big(\\dfrac{C_c}{C}\\Big)^{\\alpha_C}`}</Math>

Kaplan 论文给出的指数大约是 α_N≈0.076、α_D≈0.095、α_C≈0.050。指数越大，loss 对那个变量越敏感——所以**数据比参数稍微更值钱一点**，同等“加 10 倍”，加数据降的 loss 比加参数多。

## 算力固定时，到底怎么分

实验 1、2 各自变一个变量已经能看到趋势，但工程师真正关心的是另一个问题：**总预算只有这么多 FLOPs，应该把它花在更大的模型上，还是更多的 token 上？**

这就是 Chinchilla 论文最值钱的一张图。把 loss 写成 N 和 D 的二元函数，再把 D 用 C/(6N) 替换，得到一条只关于 N 的曲线：

<Math block>{`\\hat L(N \\mid C) = E + \\dfrac{A}{N^{\\alpha}} + \\dfrac{B}{(C/6N)^{\\beta}}`}</Math>

曲线呈 U 形——两端均处劣势，最低点对应该算力下的最优配比。

<ComputeOptimalFrontier />

切换不同的算力档位，最低点会沿着一条斜率约 1 的射线移动，对应的就是 D ≈ 20 N。这条规律解释了过去几年大模型路线为什么会有那么大的转向：

GPT-3 时代的常见做法是尽可能扩大模型、数据量相对有限——175B 参数仅训练 300B token，比值 1.7。Chinchilla 论文按 U 形最低点反推，给出反直觉结论：同等算力下，70B 参数 + 1.4T token 应优于 175B + 300B，且推理成本仅为 1/2.5。LLaMA 与 LLaMA-2 验证了该路线；LLaMA-3 将 8B 模型训练至 15T token，将过度训练推至极端，换取更低推理成本。

<ChinchillaRatioCalculator />

将上一篇 4M 模型代入计算器可得：按 D/N=20 标准需约 80M token 方可避免过拟合。Tiny Shakespeare 仅 1M token，相差 80 倍——过拟合不可避免，工程上只能依赖 early stopping 缓解。

## 涌现：曲线之外的一类能力

幂律说的是 loss 平滑下降。但研究者很快发现，把"loss"换成“做对某项任务的比例”，画出来的曲线常常长得不一样。一些能力在小模型上几乎是 0，到了某个参数门槛突然蹦到接近 100%——这种被称为“涌现能力”（emergent abilities）。

<EmergenceVsSmoothChart />

典型例子是多步算术、Chain-of-thought 推理、跟随复杂指令。10B 参数以下基本不会，到 60B+ 就开始蹦，再大一点就稳定了。**Wei 2022** 的论文里列了几十项这样的任务。

涌现到底是不是真实的“相变”还在争论。Schaeffer 2023 的一个反驳是：很多涌现指标用了离散的 0/1 评分（必须完全答对才算 1），把光滑的概率曲线投影成了陡峭的台阶；如果换成 token-level log-likelihood 这种连续指标，曲线又重新变平滑。两边都有道理：从工程视角看，台阶的存在意味着**如果你需要某个能力，往小模型上加再多算力可能也不会冒出来，必须跨过那个参数门槛**——这一点对预算分配有非常实际的影响。

## 回到上一篇的过拟合

上一篇 4M 模型 / 267K token / 比值 0.06，距离 Chinchilla 的 20 差了 333 倍。两条出路都摆在那里：把模型缩到 ~13K（学不出东西），或者把数据加到 80M token（数据本身就只有 1M）。这就是为什么教学项目里只能接受过拟合，靠 early stopping 把损失降到最小。

工业界常态是另一极端：互联网文本达数十 TB，再大的模型也无法穷尽。该规模下「模型越大越好」近似成立——按 Chinchilla 核算后，token 数才是成本控制的关键。

## 和工业界的距离

| 环节 | 这个项目 | 工业界 |
|------|---------|--------|
| 参数范围 | 20K ~ 10M | 1B ~ 1T |
| 数据范围 | 100K ~ 1M tokens | 1T ~ 15T tokens |
| FLOPs | ~10¹⁰ | ~10²⁴（差 14 个数量级） |
| 验证的规律 | 定性趋势一致 | 精确拟合幂律系数 |
| 实用意义 | 解释为什么会过拟合 | 决定一笔几亿美元的算力怎么花 |

OpenAI 决定 GPT-4 的模型规模与训练 token 量，正是将 1B 以下小模型按该幂律外推所得。本实验规模相差 14 个数量级，曲线形态完全一致——这正是 scaling law 的价值：以低成本预测高成本系统行为。
