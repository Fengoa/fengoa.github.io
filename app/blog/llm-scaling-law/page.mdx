# Scaling Law：更大一定更好吗

<SeriesNav series="llm" />

上一篇训练了一个 4M 参数的模型，严重过拟合——参数比数据多 15 倍。直觉上解法有两个：缩小模型，或者增大数据。

但到底该缩多少、加多少？不是拍脑袋能定的。2020 年 OpenAI 发了一篇论文，2022 年 DeepMind 的 Chinchilla 论文做了修正，给出了一个经验公式：

```text
给定固定的算力预算 C（FLOPs），
最优的参数量 N 和训练数据量 D 满足：
  N ≈ D / 20

即：每个参数应该"看"大约 20 个 token。
```

这就是 Scaling Law——模型效果和参数量、数据量、算力之间的幂律关系。这篇用实验验证它。

---

## 实验设计

三组实验，控制变量法：

| 实验 | 固定 | 变量 | 看什么 |
|------|------|------|--------|
| 1 | 数据量 + 步数 | 模型大小（6 种） | 参数量 vs loss |
| 2 | 模型大小 | 数据量（5%~100%） | 数据量 vs loss |
| 3 | 算力预算（FLOPs） | 参数/数据配比 | 谁是最优平衡点 |

数据用字符级 Shakespeare（100 万 token），模型从 ~20K 到 ~10M 参数。

---

## 实验 1：参数量 vs Loss

固定训练 5000 步，看不同大小模型的 val loss：

```text
模型         参数量         Val Loss
────────────────────────────────────
tiny         53K            2.07
small        228K           1.88
base         403K           1.75
medium       1.8M           1.52
large        3.2M           1.51
xlarge       10.7M          1.68  ← 过拟合了！
```

规律：**参数量从 53K 增到 3.2M（60 倍），loss 从 2.07 降到 1.51**。但 xlarge（10.7M）反而比 large 差——因为数据只有 100 万 token，撑不住 1000 万参数的模型，开始过拟合了。

这就是幂律（power law）：

```text
L(N) ≈ a × N^(-α)

Loss 和参数量 N 呈幂律关系，α ≈ 0.07（OpenAI 论文的实测值）
```

不是线性关系。参数量翻倍，loss 不会减半，只会减少一小点。要把 loss 从 1.8 降到 1.5，可能需要参数量 ×10。

---

## 实验 2：数据量 vs Loss

固定 base 模型（~400K 参数），变训练数据量：

```text
数据比例       Token数         Val Loss
──────────────────────────────────────
5%             50K             2.70
10%            100K            2.24
20%            201K            2.05
50%            502K            1.91
100%           1.0M            1.76
```

规律：**数据量翻倍，loss 也按幂律下降**。从 5% → 20% 提升最大（2.70 → 2.05），之后边际收益递减。

当数据不足时（5%），模型很快过拟合——train loss 很低但 val loss 很高。数据充足时（100%），train 和 val 差距小，说明模型真正在"学"而不是"背"。

---

## 实验 3：固定算力，找最优配比

这是最关键的实验。给定固定的计算预算（FLOPs ≈ 6ND），怎么分配给模型大小 N 和数据量 D？

```text
配置              参数量      Token数        Val Loss
───────────────────────────────────────────────────
小模型+多数据      54K        2.0M           2.59
中小模型           228K       2.0M           2.45
中模型             403K       2.0M           2.38
中大模型           1.8M       2.0M           2.20
大模型+少数据      3.2M       2.0M           2.10  ← 最优
```

在我们这个实验里，固定 500 步 × batch_size=64 × ctx=64 = 2M tokens 的算力预算下，**大模型 + 少数据赢了**——因为 2M tokens 对 3.2M 参数来说还没到过拟合的边界。

但如果把步数加到 5000（实验 1 的结果），xlarge(10.7M) 就过拟合了。这正是 Chinchilla 的结论：**最优配比存在一个平衡点，参数量和数据量需要同步扩大**。

这就是 Chinchilla 的核心发现。之前 GPT-3 的做法是"尽可能大的模型，数据凑合用"（175B 参数只训了 300B token，比值 1:1.7）。Chinchilla 证明了 70B 参数训 1.4T token（比值 1:20）效果更好，而且推理更快、成本更低。

---

## Scaling Law 的数学形式

三条幂律：

```text
L(N) = (N_c / N)^α_N        # 参数量 scaling，α_N ≈ 0.076
L(D) = (D_c / D)^α_D        # 数据量 scaling，α_D ≈ 0.095
L(C) = (C_c / C)^α_C        # 算力 scaling，α_C ≈ 0.050
```

含义：
- 参数量增加 10x → loss 减少约 17%
- 数据量增加 10x → loss 减少约 20%
- 算力增加 10x → loss 减少约 11%

所以**数据比参数更重要**（α_D > α_N）。同样的资源优先加数据。

## 对我们第 5 篇过拟合的解释

回看上一篇的问题：

```text
模型: 4.17M 参数
数据: 267K tokens
比值: N/D = 4.17M / 267K ≈ 15.6

Chinchilla 最优比值: N/D ≈ 1/20 = 0.05
我们的比值: 15.6
差了 300 倍！
```

难怪过拟合。如果要让 4M 模型不过拟合，需要 ~80M token（约 80MB 文本）。或者反过来，267K token 只能支撑 ~13K 参数的模型。

## 实际影响

Scaling Law 改变了整个行业的方法论：

| 之前（GPT-3 时代） | 之后（Chinchilla 之后） |
|---|---|
| 尽可能大的模型 | 最优的模型/数据配比 |
| 175B 参数，300B token | 70B 参数，1.4T token |
| 推理成本极高 | 同等效果，推理成本低 |

LLaMA 就是 Chinchilla 路线的产物——用 7B/13B/33B/65B 的"小"模型，训更多数据（1.4T token），效果比 GPT-3 好，推理便宜得多。

---

## Emergent Abilities（涌现能力）

Scaling Law 说的是"loss 平滑下降"。但有些能力不是平滑出现的——模型小的时候完全不会，大到某个阈值后突然就会了：

- **算术**：< 10B 参数时几乎不会，> 100B 突然会了
- **Chain-of-thought**：小模型做不到"一步步推理"，大模型可以
- **代码生成**：需要足够大的模型才能理解语法结构

这些叫"涌现能力"，目前还没有很好的理论解释。但实践上说明：**如果你需要某种能力，可能需要模型大到某个门槛，而不是线性提升**。

## 和工业界的距离

| 环节 | 这个项目 | 工业界 |
|------|---------|--------|
| 参数范围 | 20K ~ 10M | 1B ~ 1T |
| 数据范围 | 100K ~ 1M tokens | 1T ~ 15T tokens |
| FLOPs | ~10^10 | ~10^24 (差 14 个数量级) |
| 验证的规律 | 定性趋势一致 | 精确拟合幂律系数 |
| 实用意义 | 理解为什么过拟合 | 决定花几亿美元怎么分配 |

规律是一样的。OpenAI 决定 GPT-4 用多大模型、训多少数据，就是用 scaling law 在小模型上预测出来的。我们的实验也能看到同样的趋势——只是规模差了 14 个数量级。
