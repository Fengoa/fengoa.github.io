# Attention 到底在做什么

<SeriesNav series="llm" />

上一篇训练好的 MiniGPT 输入 “KING RICHARD:”，能续出一段像样的台词。模型一边吐字，一边在内部做一件事：每写下一个新字符，都回头看看前面已经有的几十个字符，给每个位置打分，再决定这次主要参考哪几个。这个“回头看”的机制就是 self-attention。

把它放在更小的场景里看会更直观。生成 “his ___” 时，对预测最有帮助的是 “king” 和 “said”，而 “the”、“to” 几乎没什么信息量。MLP 那一篇是按位置给固定权重，第 1 个位置永远是同一份贡献，第 16 个位置也是。Attention 换了个思路：每次根据当前在写的内容，临时决定哪些位置权重高、哪些可以略过。

<MLPvsAttention />

差别看起来不大，影响却很关键。窗口可以放得很长，不必担心远处位置被一视同仁地稀释；同样一段历史，写不同的下一个词时也能切到不同的关注分布。

## Q、K、V 是什么

整个 attention 围绕三样东西展开：query、key、value。每个 token 的 embedding 同时被三套权重映射成三种身份——它在找什么、它对外暴露什么、它真正携带什么信息。

<QKVProjection />

写成式子就是三次矩阵乘法：

<Math block>{`Q = X W_q, \\quad K = X W_k, \\quad V = X W_v`}</Math>

`W_q`、`W_k`、`W_v` 都是可学习参数。模型不会一开始就知道哪种 query 该匹配哪种 key，是训练把这三套矩阵磨出来的。同一个 embedding 走完三条线，就拥有了三种身份，可以分别参与后面的匹配和加权。

## 一次 attention 计算

继续用 “I am a cat” 这四个 token 走一遍流程。先算每对位置的匹配分，再加 mask，再 softmax，最后按权重去拿 value。这三步可以在下面这张表里直接切换：

<AttentionScoreMatrix />

第一步是点积，每对 (i, j) 的分数等于 Q[i] 和 K[j] 的内积，再除以 `\sqrt{d}`：

<Math block>{`\\text{score}(i, j) = \\frac{Q_i \\cdot K_j}{\\sqrt{d_k}}`}</Math>

除以 `\sqrt{d_k}` 是为了控制数值幅度。维度一大，点积也跟着变大，softmax 就容易落在饱和区，梯度传不回来。

第二步是因果 mask。语言模型从左往右生成，位置 i 不能偷看 i 之后的内容，所以未来位置的 score 直接设成 `-∞`。softmax 之后那些位置自然就是 0。

第三步是 softmax 归一，每一行加起来是 1，这就是真正的注意力权重。最后一步用这套权重对 V 做加权求和：

<Math block>{`\\text{Attention}(Q, K, V) = \\text{softmax}\\!\\left(\\frac{Q K^\\top}{\\sqrt{d_k}}\\right) V`}</Math>

每个位置的输出，都是它“关心”的那些位置的 value 按权重混合的结果。看 “cat” 这一行，权重分别是 0.31、0.27、0.22、0.25，输出就是这四个 value 按这套比例加起来。

写成代码就是几行：

```python
def attention(Q, K, V, mask):
    d = Q.shape[-1]
    scores = Q @ K.transpose(-2, -1) / math.sqrt(d)
    scores = scores.masked_fill(mask == 0, float("-inf"))
    weights = F.softmax(scores, dim=-1)
    return weights @ V
```

整个 attention 就是这一段。剩下的工程复杂度——多头、缓存、Flash——都是在这个核之外加包装。

## 多头：让模型同时学几种关注模式

一组 `W_q / W_k / W_v` 只能学到一种关注模式。但语言里要照顾的关系很多：有时候要看前一个字符做拼写预测，有时候要看远处的角色名做格式对齐，有时候要看中等距离的词内结构。一组权重很难同时兼顾。

做法是并行开多个 head，各自有一套独立的 `W_q / W_k / W_v`，最后把输出拼起来再过一个 `W_o`：

<Math block>{`\\text{MultiHead}(X) = \\text{Concat}(\\text{head}_1, \\dots, \\text{head}_h) \\, W_o`}</Math>

MiniGPT 用 4 个 head，每个 head 32 维，拼起来正好是 128 维 embedding 大小。参数量和单头 128 维基本一致，但表达能力强很多。

把训好的 MiniGPT 拿出来，输入 “KING RICHARD:”，看每个 head 在做什么：

<MultiHeadPatterns />

第 0 层里 Head 2 学到的是“看前一个字符”，几乎就是个 bigram。第 1 层里 Head 2 走到了另一个极端，几乎所有位置都把权重压在开头几个字符上——它在记住“这一段是以 K 开头的角色名”。其他几个 head 落在递减分布或者中距离模式上，分担综合上下文的活。

没有人写过任何规则告诉模型“Head 2 你去学 bigram”。这种分工是梯度下降自己找出来的——把任务分散到几个 head 上，整体损失更低。

## Attention 和 MLP 的差别在哪

MLP 也能算两个位置之间的关系：把窗口里所有 embedding 拼起来送进全连接，权重之间的耦合就是某种关系。但这种关系是“位置×位置”的，针对位置编号固定下来的。换一段输入，第 1 个位置和第 16 个位置之间的处理方式不变。

Attention 把这件事换成了“内容×内容”。两个位置之间的权重由它们各自的 query 和 key 临时决定，所以同一个位置在不同句子里、对不同的下一个词，都可以呈现出不同的关注分布。这也是为什么 attention 能撑起长上下文：它的代价随长度增长，但表达能力没有像 MLP 那样被位置框死。

## 和工业界的距离

| 环节 | 这个项目 | 大模型 |
|------|---------|-----------|
| 注意力类型 | 标准 Multi-Head | Grouped-Query Attention |
| Head 数 | 4 | 数十到上百 |
| 上下文长度 | 64 | 128K 起跳 |
| 位置编码 | 学到的绝对位置 | RoPE |
| 效率优化 | 没做 | Flash Attention、KV Cache |

公式部分一字不差，差的全是工程：怎么算得更快、存得更少、看得更远。后续几篇会一个一个讲清楚。
