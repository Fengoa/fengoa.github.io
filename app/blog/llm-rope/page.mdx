# 位置编码：RoPE

<SeriesNav series="llm" />

把一句话喂给 Attention，它只看 Q 和 K 的内积，谁排在前、谁排在后完全无感。"dog bites man" 和 "man bites dog" 在它眼里是同一锅词向量。要让模型看出顺序，只能在外面给每个 token 贴一个表示位置的标签。

GPT-2 的做法挺直接：开一个 `(ctx, n_embd)` 的位置 embedding 表，训练时学出来，推理时按位置查。问题是这张表的行数在训练时就钉死了。训练时 ctx=64，推理时来个第 65 个 token，根本没有对应的位置向量。模型不会优雅地外推，只会原地崩坏。

<PositionEmbeddingFailure />

RoPE 换了个思路：不再把位置当成一个要学的向量"加"上去，而是让位置变成 Q、K 在做内积之前要"转"过的角度。这样位置信息进了几何里，外推也就自然了。

## 绝对位置编码到底卡在哪

GPT-2 的写法是这样：

```python
x = token_embedding(idx) + position_embedding(pos)
```

`position_embedding` 是一个 lookup table，行数等于训练 ctx。第 65 个 token 没出现在训练里，对应那一行从来没被梯度更新过——拿出来用，里面就是初始化时的随机数，叠到 token embedding 上不啻于注入噪声。

有人会想：那把位置表初始化大一点，开到 100 万行？没用。没被训练过的位置，attention 学到的相对位置先验也跟着失效。从根上说，绝对位置编码把"长度"这件事写死在了参数里。

## RoPE 的核心想法

RoPE 不动 embedding，它动 Q 和 K。每个位置对应一个旋转矩阵 <Math>{`R_m`}</Math>，在算 attention 之前先把 Q、K 转一下：

<Math block>{`\\text{score}(i, j) = (R_i\\, q_i)^\\top (R_j\\, k_j)`}</Math>

旋转矩阵是正交的，转置就是逆。展开一算：

<Math block>{`(R_i q)^\\top (R_j k) = q^\\top R_i^\\top R_j k = q^\\top R_{j-i}\\, k`}</Math>

注意力分数只跟 <Math>{`j - i`}</Math> 有关，不依赖绝对位置。第 3 个 token 看第 1 个，和第 100 个 token 看第 98 个，attention 模式是同一回事。模型不需要为每个绝对位置单独学个 embedding，相对位置自然落进了几何关系里。

## 旋转的几何直觉

二维平面上一个向量逆时针转 <Math>{`\\theta`}</Math>，矩阵长这样：

<Math block>{`R(\\theta) = \\begin{bmatrix} \\cos\\theta & -\\sin\\theta \\\\ \\sin\\theta & \\cos\\theta \\end{bmatrix}`}</Math>

RoPE 把 <Math>{`d`}</Math> 维向量两两配对，每对就是一个二维平面上的向量。第 <Math>{`i`}</Math> 对的旋转频率是：

<Math block>{`\\omega_i = \\theta^{-2i/d}, \\quad \\theta = 10000`}</Math>

位置 <Math>{`m`}</Math> 给第 <Math>{`i`}</Math> 对带来的旋转角是 <Math>{`m \\cdot \\omega_i`}</Math>。所有维度共用同一个位置 <Math>{`m`}</Math>，但旋转速度不一样：低维 <Math>{`\\omega`}</Math> 大，转得快；高维 <Math>{`\\omega`}</Math> 小，转得慢。

<Rope2dRotation />

这一组频率刚好像一组钟表的指针。秒针跑得快，每分钟一圈，分辨细节；时针几乎不动，分辨大段。看一眼三根针，时刻是确定的。

<RopeFrequencyClock />

## 实现：复数视角下三行代码

把维度配对、转角度这两件事写出来，最自然的语言是复数。一对实数 <Math>{`(x_{2i}, x_{2i+1})`}</Math> 看作复数 <Math>{`x_{2i} + i x_{2i+1}`}</Math>，乘上单位复数 <Math>{`e^{im\\omega_i}`}</Math> 就完成了旋转。

```python
def precompute_freqs(dim, max_seq_len, theta=10000.0):
    freqs = 1.0 / (theta ** (torch.arange(0, dim, 2) / dim))
    t = torch.arange(max_seq_len)
    angles = torch.outer(t, freqs)               # (seq_len, dim/2)
    return torch.polar(torch.ones_like(angles), angles)  # 复数

def apply_rotary_emb(q, k, freqs):
    q_complex = torch.view_as_complex(q.reshape(*q.shape[:-1], -1, 2))
    k_complex = torch.view_as_complex(k.reshape(*k.shape[:-1], -1, 2))
    q_out = q_complex * freqs                    # 旋转
    k_out = k_complex * freqs
    return torch.view_as_real(q_out).flatten(-2), torch.view_as_real(k_out).flatten(-2)
```

预计算频率表只在初始化时跑一次，每步前向只花一次复数乘。它没有可学参数，也没有 lookup table，长度就不再是硬约束。

## 同一个模型，三种位置编码

用 2 层 128 维的小模型在 Tiny Shakespeare 上跑 5000 步，分别开关位置编码。表里 RoPE 参数最少（不需要存位置 embedding 表的 8192 个参数），val loss 还最低：

| 位置编码 | 参数量 | val loss | 与 RoPE 差 |
|---|---:|---:|---:|
| 无位置 | 411,136 | 1.94 | +0.36 |
| 绝对学习 | 419,328 | 1.65 | +0.07 |
| 正弦 | 411,136 | 1.62 | +0.04 |
| RoPE | 411,136 | 1.58 | 0 |

参数更少，效果更好——只是因为参数量小很多的位置 embedding 表本来就没什么"信息密度"，把它替换成纯几何变换反而省事。

真正能把它们彻底拉开的是外推：训练长度还是 64，推理时把序列拉到 256，看 loss 怎么变。

<ExtrapolationComparison />

绝对学习从 1.65 涨到 2.5+，基本生成不出连贯文本。RoPE 从 1.58 涨到 1.65，肉眼可见的稳定。正弦编码介于中间，能撑一段，远了也撑不住。

## 工业界为什么全部转向 RoPE

LLaMA、Qwen、Mistral、GPT-NeoX、DeepSeek 等公开权重的开源模型，几乎清一色用 RoPE。原因不是哪一条特别突出，而是它在几个维度上同时占便宜。

不需要额外参数，位置信息编码进旋转角；天然只依赖相对位置；和 Flash Attention 兼容（旋转可以 fuse 进 kernel，无需改 attention 主体）；远距离 token 的旋转角差大，点积幅度自然衰减，相当于自带一种局部性归纳偏置。

外推能力是它压倒性的卖点。从 LLaMA 2 的 4K 一路往上，到 LLaMA 3 的 8K、Qwen 2.5 的 128K，背后都是 RoPE 的几何性质支撑。具体的扩展手段——NTK-aware Scaling、YaRN、Position Interpolation——本质上都在调旋转频率的底数 <Math>{`\\theta`}</Math> 或频段，而不是改公式本身。

## 和工业界的距离

| 环节 | 这个项目 | LLaMA / Qwen 级别 |
|---|---|---|
| 实现 | 基础 RoPE，固定 <Math>{`\\theta = 10000`}</Math> | NTK-aware / YaRN，动态调整 <Math>{`\\theta`}</Math> |
| 上下文 | 64 → 256 外推 | 4K → 128K 外推 |
| 优化 | 纯 Python 复数乘 | Fuse 进 Flash Attention CUDA kernel |
| 频率分配 | 全部维度均匀分配 | 部分模型保留少量绝对维度（hybrid） |

数学骨架完全一致。差别在于工业界要把 RoPE 推到训练时几十倍的长度，需要在频率分配和插值方式上做更精细的设计。
