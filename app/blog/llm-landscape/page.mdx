## 这张图怎么看

整张图是从下游往上游读的：底层是原料，越往上越接近用户。

数据层将人类知识编码为 token，界定模型认知边界。架构层以 Transformer 为骨架，差异体现在 Attention 变体与 FFN 是否采用 MoE。预训练填充参数，对齐使模型按指令回答并终止纯续写，推理部署解决工程化落地，应用层将能力封装为产品。

每两层之间有一个连接器，写着上一层产出的中间产物。比如架构层产出『随机初始化的网络』，喂给预训练得到 base model；base model 经过 SFT/DPO 变成 chat model，再经过推理优化变成线上服务。这条主链每个节点都对应系列里的一篇文章，整套技术栈是闭环的。

紫色斜体的部分是这两年还在快速变化的方向：合成数据、MoE、长上下文、多模态、Agent。文章正文不会全部展开，但放在这里是为了说明哪些东西已经定型、哪些还在动。

横轴为发布时间，纵轴为参数量（log 刻度），气泡大小代表社区影响力。MoE 模型以虚线小气泡标注每次实际激活参数量——同为 671B，DeepSeek-V3 每次仅激活 37B，成本接近 7B 稠密模型。

闭源模型（GPT-4、Claude、Gemini）没画在图上，因为它们既不公布参数也不公布训练成本。但从公开能力对比看，这条开源曲线和闭源旗舰的差距已经从 2023 年初的 18 个月缩到了 6 个月以内。


## 前沿方向

### MoE 把容量和算力解耦

MoE 的想法很简单：把 FFN 拆成很多个『专家』，每个 token 只选 top-k 个激活，剩下的不参与计算。这样总参数可以堆得很大（容量），但每次前向算的参数还是一小部分（成本）。

写成公式就一行——路由器先给 N 个专家打分，挑分数最高的 k 个，再把它们的输出按 softmax 权重加起来：

<Math block>{`y = \\sum_{i \\in \\text{TopK}(g(x))} \\text{softmax}(g(x))_i \\cdot E_i(x)`}</Math>

<MoeRoutingAnimation />

代价是路由器要学得好——不能让所有 token 都涌向同一个专家（负载不均），也不能让相邻 token 的路由乱跳（训练不稳）。Mixtral 用 8 个专家激活 2 个，DeepSeek-V3 走得更激进：256 个专家激活 8 个，外加几个共享专家保底。

为何 MoE 当前受关注？训练 671B 稠密模型单次实验需耗资上千万美元，参与者有限。671B-MoE 实际激活仅 37B，训练吞吐接近 70B 稠密模型，普通团队（数百张 GPU）亦可参与。开源生态中 MoE 已成为新模型的默认架构。

### 多模态走向统一表征

早期多模态模型是『先用 ViT 把图片编码成向量，再喂给 LLM』——CLIP、LLaVA 都是这套。模型实际上有两个大脑，靠 projector 把它们粘起来。

GPT-4o 和 Gemini 走得更远：图片、文本、音频、视频全部 token 化，送入同一个 Transformer。从输出端看，模型可以直接生成文字、图像、音频，无需再切换模态。Sora、4o 的语音模式都是这条路线的产物。

工程上仍有多项挑战——视频 token 数量庞大（每秒 30 帧 × 每帧上千 token），压缩策略需平衡信息保留；跨模态 attention 需避免相互干扰。上述问题在 2024 年仍在活跃研究中。

### Agent 开始能用了

『让模型用工具』这件事 2023 年就在喊，但真正可用的实现不多。难点在长程任务的规划——一个步骤错了，后面全错；单次 API 调用本身通常不是瓶颈。

2024 年下半年风向变了。Claude 的 Computer Use 能直接操作浏览器和桌面，Cursor 能在仓库级代码里做多文件改动，Devin 在 SWE-bench 上做到 13%。共同特点是：模型能在出错时回退、试错、查日志、再试，并据此调整策略。

支撑这件事的是两件事的叠加：一是模型本身推理能力变强了（o1/R1 那条线），二是工程上把『让模型循环 50 步』的反馈系统搭起来了。MCP 协议在 2024 年底出现就是一个标志——它把『模型怎么和外部工具说话』这件事标准化了。

### 长上下文从 4K 走到 1M

GPT-3 的 2K → GPT-3.5 的 4K → Claude 2 的 100K → Gemini 1.5 的 1M。这条线背后是三件事配合：RoPE 的外推方案（YaRN、LongRoPE），分布式 Attention（Ring Attention 把序列切到多卡），以及 KV Cache 的压缩（PagedAttention、量化）。

但长上下文有个隐藏代价：『大海捞针』评测好看不代表真用得上。100K 的窗口塞 99K 噪声 + 1K 关键信息，模型的实际利用率是另一回事。这也是为什么 RAG 没有被长上下文淘汰——好的检索仍然比塞一整本书更靠谱。

## 和推荐系统的对比

| | 推荐系统 | 大模型 |
|---|---|---|
| 核心任务 | 给用户找到感兴趣的物品 | 给 prompt 生成合理的续写 |
| 数据 | 用户行为日志 | 互联网文本 |
| 模型 | DeepFM / DIN / MMoE | Transformer |
| 特征 | 手工特征工程 | 直接学 token representation |
| 服务 | 50ms 延迟，万级 QPS | 几秒延迟，百级 QPS |
| 评估 | AUC / NDCG / A/B | Perplexity / Human Eval / ELO |

两个领域骨子里是一回事：从数据中学模式，再在线服务。推荐系统学的是用户偏好，大模型学的是语言规律。工程化的套路也几乎相同——离线训练、在线推理、缓存加速、监控报警，连分布式训练那套（DP/TP/PP）都是从大模型这边长出来反哺到推荐系统的。

差别主要在两件事。一是延迟和吞吐——推荐系统要在 50ms 内出结果，大模型一次回答几秒钟是常态。这导致推荐系统的工程优化重心在『极致低延迟』，大模型的重心在『单位算力出更多 token』。二是特征 vs 表示——推荐系统的胜负还在很大程度上取决于特征工程做得好不好，大模型已经把这一步内化了，但代价是模型本身要大几个数量级。


## 下一步

主链路走完后，往下深入大概有四个方向。

最直接的路径是在真实开源模型上完成端到端流程：下载 Qwen-2.5-7B 或 LLaMA-3-8B，构造 SFT 数据并微调，执行 DPO 对齐，量化至 4bit，以 vLLM 部署。该路径串联系列 14 篇文章，完成后对各环节的理解将显著加深。

第二个是做一个真实的 RAG 应用。给自己的笔记、邮件或者团队文档建个索引，做一个能回答私有知识的助手。chunking 策略、embedding 选型、检索质量调优这些问题在真实数据上和 toy 数据上完全不是一回事。

第三个是补论文。挑一个感兴趣的方向，按上面参考清单刷一组——比如『高效注意力』那一组从 Flash Attention 一路读到 PagedAttention，每篇都对照实现看一遍。

第四是编写 GPU kernel。阅读 Flash Attention 的 Triton 实现并自行实现简化版本，完成端到端验证。该步骤进入硬件层优化。是否投入取决于工作场景，但至此技术栈可视为贯通。

基础链路已完成，下一步是在真实场景中持续迭代优化。
