## 我们做了什么

| 层 | 做了 | 没做 |
|---|---|---|
| 数据层 | BPE tokenizer、字符级编码 | 大规模数据清洗、去重 |
| 架构层 | Attention、多头、FFN、LayerNorm、RoPE、GQA | SwiGLU、RMSNorm、MoE |
| 预训练 | 完整训练循环、Scaling Law 实验 | 分布式训练、数据并行 |
| 对齐层 | SFT + LoRA、DPO loss | 大规模 RLHF、Safety |
| 推理层 | KV Cache、GQA、量化概念 | Flash Attention kernel、PagedAttention |
| 应用层 | RAG 概念、部署方案 | Agent、Tool Use、多模态 |

核心链路走通了。每一层都理解了原理和实现方式。缺的部分要么需要更大规模（分布式训练），要么需要 CUDA 底层开发（Flash Attention），要么需要大量人工标注（RLHF）。

## 前沿方向

### MoE（Mixture of Experts）

不是所有参数每次都用——每个 token 只激活部分"专家"：

```text
总参数: 671B
每次激活: ~37B（只用 6%）
→ 效果接近 671B 全模型，成本接近 37B 模型
```

DeepSeek-V3 和 Mixtral 用的就是这个。

### 多模态

一个模型同时处理文本、图片、音频、视频：

```text
输入: [图片 token] + [文字 token]
→ 统一的 Transformer 处理
→ 输出: 文字/图片/代码
```

GPT-4o、Gemini、Qwen-VL 都是多模态模型。

### Agent

让模型使用工具、分步推理、自主完成复杂任务：

```text
用户: "帮我查最近的天气并订一家适合的餐厅"
模型:
  1. 调用天气 API → 得到"晴天 25°C"
  2. 推理: 晴天适合户外
  3. 调用餐厅搜索 → 筛选有露台的
  4. 返回推荐结果
```

### 长上下文

从 4K → 32K → 128K → 1M token。让模型能"读"整本书、整个代码库。

关键技术：RoPE 外推（YaRN）、Ring Attention（分布式长序列）。

## 和推荐系统的对比

| | 推荐系统 | 大模型 |
|---|---|---|
| 核心任务 | 给用户找到感兴趣的物品 | 给 prompt 生成合理的续写 |
| 数据 | 用户行为日志 | 互联网文本 |
| 模型 | DeepFM / DIN / MMoE | Transformer |
| 特征 | 手工特征工程 | 直接学 token representation |
| 服务 | 50ms 延迟，万级 QPS | 几秒延迟，百级 QPS |
| 评估 | AUC / NDCG / A/B | Perplexity / Human Eval / ELO |

两个领域的共同点：**都是从数据中学模式，然后在线服务**。推荐系统学"用户偏好"，大模型学"语言规律"。工程化的思路也一样——离线训练、在线推理、缓存加速、监控报警。
