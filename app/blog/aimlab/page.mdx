# 从零写一个浏览器里的 3D 瞄准训练器

最近发现一个实用的库，[React Three Fiber](https://r3f.docs.pmnd.rs/getting-started/introduction)，可以用 React 组件描述 3D 场景，大幅降低了 3D 交互产品的开发门槛。

于是我写了一个小型的瞄准训练工具：鼠标锁入画面后，移动鼠标即可环顾四周；屏幕正中的准星扫过一片蓝色小球，左键扣动，最近的那颗亮起分数、迸成光点，随后转移到另一处。整套产品可在纯浏览器环境中流畅运行。

下面按我实际开发的顺序展开：先解决「人站在哪里」的问题，再解决「打什么」的问题，最后解决「手里拿什么」的问题。每一步都记录了开发过程遇到的真实问题与对应解法。

## 让玩家站在一个有环境的世界里

一个误解是场景必须用类似 glb 格式的 3D 模型，但其实不然，可以巧妙的用一张全景图片来模拟环境。

最初的直接思路是给场景加一个背景。three.js 提供 `scene.background` 直接贴图，但实测后它会被 tone mapping 处理——全景图的暗部被提亮、亮部被压暗，整体观感像蒙了一层灰。而且 `scene.background` 只是一张背景贴图，既会被额外调色，也完全不参与任何光照与反射，金属枪身与靶子并不会从中映出环境。

因此改为自建一个天空球，将全景图贴到内壁：

```tsx
<mesh>
  <sphereGeometry args={[100, 60, 40]} />
  <meshBasicMaterial map={texture} side={THREE.BackSide} toneMapped={false} />
</mesh>
```

`side={THREE.BackSide}` 是关键：普通球体仅渲染外表面，而我们需要观察球的**内部**，因此翻转渲染面。`toneMapped={false}` 让贴图颜色原样输出，不被额外调色。球体半径取 100，足以将全部游戏内容包裹在内。

不过天空盒本质仍是一张贴图，它自己并不会参与光照——金属枪身与靶子想「映出周围环境」，得另开一盏基于图像的环境光。做法是把同一张全景图赋给 `scene.environment`，three.js 会据此做 IBL（Image-Based Lighting），金属与清漆表面便有了可反射的周遭：

```ts
tex.mapping = THREE.EquirectangularReflectionMapping;
tex.colorSpace = THREE.SRGBColorSpace;
scene.environment = tex;        // 供金属 / 清漆表面反射
scene.environmentIntensity = ...; // 反射强度可调
```

天空盒负责「背景长什么样」，IBL 负责「物体表面反射什么」，两件事分开，画面才既真实又可控。

全景图采用一张等距柱状投影（equirectangular）的暗色室内射击场贴图（宽高比 2:1）。对应的提示词如下，可以给任意AI工具来生成。

```text
生成一张等距圆柱投影(equirectangular)的360度全景图，比例是2:1。
主题是科幻未来感的射击训练场室内：深灰/暗色调金属墙面、橙红色点缀灯带和警示条纹、深色网格地面、工业风暗调照明、4K清晰度（3840×1920像素）、2:1等距圆柱投影，无缝拼接。
无人物、无文字、无水印。不要有人物、不要文字、不要水印，画面要能左右无缝拼接、无透视扭曲。
```


## 让世界里有可命中的目标

靶子是一颗金属质感的球体，使用 `meshPhysicalMaterial`：高 `metalness` 让它像抛光金属球，叠加 `clearcoat` 清漆层增加一层高光，再用一点 `emissive` 自发光保证暗处也看得见；球心再叠一个黄色小圆点，方便快速定位对准：

```tsx
<group position={position}>
  {/* 抛光金属球 */}
  <mesh userData={{ targetId: id }}>
    <sphereGeometry args={[size, 48, 48]} />
    <meshPhysicalMaterial
      color="#3b6fe0" emissive="#2f6bff"
      emissiveIntensity={0.12} roughness={0.16}
      metalness={0.9} envMapIntensity={1.6}
      clearcoat={0.7} clearcoatRoughness={0.2}
    />
  </mesh>
  {/* 中心黄色小瞄准点 */}
  <mesh position={[0, 0, size * 1.01]}>
    <circleGeometry args={[size * 0.12, 16]} />
    <meshBasicMaterial color="#f59e0b" side={THREE.DoubleSide} />
  </mesh>
</group>
```

金属度拉到 0.9 意味着球体几乎只反射「环境与灯光」、自身漫反射极弱——若场景里没光，它就是一团黑。所以我额外布了几盏灯：一盏 `ambientLight` 兜底填亮暗部、一盏 `directionalLight` 给出主光方向，再加两盏橙色与一盏蓝色 `pointLight` 点光源。它们既照亮靶球，也把射击场的科幻氛围带进金属反光里。

射击训练需要让靶子分布在一个以玩家为球心的弧面上，转头才能扫到不同方向。我的做法是先生成一组固定间距的参考点网格，再在每个参考点附近做随机抖动：

```ts
export function genGridPositions(cfg) {
  const { radius, rows, cols, aHalf, eUp, eDown, gridSpacing } = cfg;
  const pts = [];
  const hSpan = Math.min((cols - 1) * gridSpacing, 2 * aHalf);
  const vSpan = Math.min((rows - 1) * gridSpacing, eUp + eDown);
  const aStart = -hSpan / 2, eStart = -vSpan / 2;
  // ... 按行列遍历，球面角 → 世界坐标
  return pts;
}
```

这里存在一个约束：若直接在世界坐标的 `x/y/z` 上叠加随机米数做抖动，球面边缘处各方向不一致，靶子容易越出边界或相互重叠。解法是**在角度空间里抖动**——先将参考点转换为 `(方位角 az, 仰角 el)`，在角度上叠加随机量，再 clamp 回合法区间，最后转回世界坐标：

```ts
const jAng = tuning.jitter / tuning.arcRadius; // 米 → 弧度
let az = base.az + (Math.random() - 0.5) * jAng;
let el = base.el + (Math.random() - 0.5) * jAng * 0.4;
const margin = Math.atan(size / tuning.arcRadius);
az = clamp(az, -tuning.arcA + margin, tuning.arcA - margin);
el = clamp(el, -tuning.arcEmin + margin, tuning.arcEmax - margin);
```

如此无论 jitter 取值多大，靶子在数学上保证不越界。避免重叠采用槽位制：每个参考点是一个槽，生成时随机选取未被占用的槽，命中后释放并重新分配。

瞄准的本质是锁定鼠标加鼠标移动驱动视角。点击画面调用 `requestPointerLock()`，此后鼠标不再受屏幕边缘限制，`mousemove` 提供的为像素增量 `movementX/Y`：

```ts
const onClick = () => {
  if (document.pointerLockElement !== gl.domElement) {
    try {
      gl.domElement.requestPointerLock();
    } catch { /* 刚退出锁定后浏览器有冷却期，捕获异常 */ }
  }
};

const onMove = (e: MouseEvent) => {
  if (document.pointerLockElement !== gl.domElement) return;
  targetYaw.current   -= e.movementX * BASE_SENS * sens; // 右移→右转
  targetPitch.current -= e.movementY * BASE_SENS * sens;
  targetPitch.current = clamp(targetPitch.current, -MAX_PITCH, MAX_PITCH); // ±85°
};
```

视角每帧**直接**赋给相机，不做任何平滑插值。原因在于准星绘制于 DOM 层正中央，子弹是从相机中心射出的射线，三者必须零延迟对齐；否则画面滞后于鼠标时，所见的准星位置与实际射出的方向将不再一致。

移动采用 WASD，方向相对当前朝向，位移乘以 `delta` 以在不同帧率下保持一致速度，人眼高度锁定 1.6 仅做平移。

命中判定利用准星位于屏幕中心这一事实，从相机中心发出射线（NDC 坐标 `(0, 0)`），检测其与哪个靶球相交：

```ts
raycaster.current.setFromCamera(new THREE.Vector2(0, 0), camera);
const meshes = getTargetMeshes().filter((m) => m.parent?.visible !== false);
const hits = raycaster.current.intersectObjects(meshes, false);
if (hits.length > 0) {
  const id = hits[0].object.userData.targetId as number;
  useGame.getState().hitTarget(id);
}
```

每个靶球挂载时注册到一个全局表（`registerTarget(id, mesh)`），命中检测仅从该表取值，不会误射天空盒。射线仅取第一个交点（最近的那颗），符合直觉。

瞄准与命中发生在 3D 场景里，但准星和分数是叠在 Canvas 之上的**独立 DOM 层**，互不干扰、也不随 3D 重渲染。准星（`Crosshair`）固定在视口正中：鼠标锁定后显示十字，未锁定时显示「点击画面锁定鼠标瞄准」的引导文字。分数面板（`HUD`）在底部中央显示大号得分与命中率（`hits / shots`），右下角是武器图标与无限弹药标记 `∞`——这是一个专注瞄准的训练器，刻意不做弹匣限制，让练习不被换弹打断。

## 让第一人称手里有把枪

靶子与瞄准齐备后，视角中若空无一物会显得单薄。取一把 GLB 武器模型挂载到相机之下即可：

```tsx
import { useGLTF } from "@react-three/drei";
import { asset } from "@/app/lib/asset";

const MODEL_PATH = asset("/models/sci-fi_bullpup_rifle.webp.glb");

export default function Weapon() {
  const { scene } = useGLTF(MODEL_PATH);
  return (
    <primitive
      object={scene}
      position={[0.7, -0.18, 0.03]}
      scale={0.55}
      rotation={[0, 0.067, 0]}
    />
  );
}
```

`position` 为相对相机的偏移：X 正向向右、Y 负向略向上、Z 正向略靠前，枪便端在屏幕右下角。原始 GLB 约 20MB，使用 `gltf-transform webp` 将内部纹理转为 WebP 后压缩至约 5MB。

枪的位置、大小、朝向几乎无法一次调准，我将这些参数全部纳入一个 Tuning 对象，拖动调试面板实时调整，定稿后将 JSON 写回代码。相机 `near` 取较小值（0.1）、枪的 Z 偏移为正，确保枪始终可见且不被天空盒遮挡。
