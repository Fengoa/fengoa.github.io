# 用模型替代手写公式做排序

之前的排序公式是 `0.5 × 召回分 + 0.3 × 评分 + 0.2 × 热度`，三个数字我自己定的。一个 18 岁女生和一个 50 岁男人拿到的排序完全相同，公式只看电影本身。

想让排序因人而异，排列组合太多了，手写不了。换成让机器从 285 万条记录里自己找规律。

---

## 训练数据

模型从例子里学。每条例子是"这个用户喜不喜欢这部电影"。

正样本（label = 1）从评分 ≥ 8 的记录里取：

```text
用户1 + 《飞越疯人院》 → 1（打了 10 分）
用户1 + 《虫虫危机》   → 1（打了 10 分）
```

负样本（label = 0）从用户没看过的电影里随机抽：

```text
用户1 + 《某恐怖片》   → 0（根本没看过）
用户1 + 《某爱情片》   → 0（根本没看过）
```

如果只给正样本，模型会觉得所有电影都好，必须同时给负样本才能学会区分。最终 57 万条正样本 + 228 万条负样本 = 285 万条。

---

## 输入和输出

输入是关于（用户，电影）这一对的所有信息：

```text
用户侧：user_id、性别、年龄段、职业
电影侧：movie_id、类型（动画/剧情/犯罪...）、平均评分、评分人数
```

输出是一个 0~1 的数字，预测这个用户喜欢这部电影的概率。推理时对候选集每部电影打分，按分数排。

---

## DeepFM 的两条路径

### FM 路径

自动学所有特征两两之间的关系：

```text
"Under 18 女性" × "动画片" → 加分
"56+ 男性" × "战争片"      → 加分
"25-34 男性" × "爱情片"    → 不加分
```

不需要手动定义规则，如果训练数据里 Under 18 女性看动画片的正样本特别多，模型自己就学到了这个配对权重该高。

### DNN 路径

FM 只看两两配对。DNN 能捕捉三个、四个特征一起出现时的效应：

```text
"Under 18 女性" + "动画片" + "高评分" + "90年代" → 很高分
同样的用户 + "动画片" + "低评分" + "60年代"      → 一般
```

就是几层全连接神经网络，把所有特征拼在一起过几轮非线性变换。两条路径的输出加在一起是最终预测。

## 训练过程

数据划分：

```text
总共 285 万条样本
  ├─ 训练集 80%（228 万条）
  ├─ 验证集 10%（28 万条）
  └─ 测试集 10%（28 万条）
```

用 early stopping，监控验证集 AUC，连续 3 轮不涨就停。实际跑了 30 轮，每轮 18 秒（M 系列 Mac GPU 加速）：

```text
Epoch  1 │ AUC 0.80 ★  ← 比瞎猜（0.5）好不少了
Epoch  5 │ AUC 0.89 ★
Epoch 10 │ AUC 0.92 ★
Epoch 20 │ AUC 0.94 ★
Epoch 28 │ AUC 0.9457 ★
Epoch 29 │ AUC 0.9457
Epoch 30 │ AUC 0.9458 ★ ← 到上限了
```

最终测试集 AUC 0.9451，和验证集 0.9458 很接近，没有过拟合。意思是随机拿一部用户喜欢的电影和一部不喜欢的，模型有 94.5% 的概率判断对哪个分更高。

---

## 过拟合长什么样

这次训练没触发早停。但如果模型更复杂数据更少，就会看到验证集 AUC 开始掉：

```text
Epoch 28 │ AUC 0.9457 ★
Epoch 29 │ AUC 0.9453   （1 轮没涨）
Epoch 30 │ AUC 0.9448   （2 轮没涨）← 在跌了
Epoch 31 │ AUC 0.9441   （3 轮没涨）← 触发早停
```

就是模型把训练集里的特殊情况记住了，比如"用户 3827 喜欢电影 1459"，但这些记忆推广不到新数据上。early stopping 在它开始背答案之前刹车。

## 效果对比

同一个用户（用户 1，Under 18 女性），同样的候选集：

```text
手写公式排序：
  1. Shawshank Redemption     [itemcf+popular+vector]
  2. Raiders of the Lost Ark  [itemcf+popular]
  3. Silence of the Lambs     [itemcf+popular]
  4. Star Wars V              [genre+itemcf]
  5. Lion King                [genre+itemcf+vector]

DeepFM 模型排序：
  1. Shawshank Redemption     [itemcf+popular+vector]
  2. Forrest Gump             [itemcf]
  3. Pulp Fiction             [itemcf]
  4. Matrix                   [itemcf]
  5. Godfather                [itemcf+popular]
```

Forrest Gump 从第 14 名跳到第 2。模型发现这类用户偏好暖的、容易共情的片子。Raiders 从第 2 掉到第 6，手写公式把它排高纯粹因为多路命中，但模型觉得它跟这个用户匹配度没那么高。

手写公式对所有用户排序一样，模型对不同用户给出不同排序。

## 代码结构

```text
recommender/
  model/
    deepfm.py          # DeepFM 网络定义（PyTorch）
  ranker.py            # 支持模型打分，手写公式作为 fallback
scripts/
  build_train_data.py  # 构造正负样本 + 特征编码
  train_deepfm.py      # 训练模型
data/processed/
  train_data.pkl       # 训练数据
  deepfm_model.pt      # 训练好的模型权重
  deepfm_config.pkl    # 模型配置
```

接口没变。前端调的还是 `GET /recommendations?user_id=1`，后端自动判断有没有模型文件，有就用模型排序，没有就 fallback 到手写公式。

## 模型是固定的吗

训练完之后参数就冻住了，942KB 的文件，线上只读取不修改。新用户注册了模型不认识，用户口味变了模型也不知道。它记住的是训练那一刻的数据分布。

工业界的做法是定期重训（每天/每周用最新数据重跑），或者增量训练（只用最近 N 天的新数据更新参数），或者在线学习（每收到一条新行为就微调一次）。这个项目是最简单的情况，离线训练一次用到下次重跑。

---

## 和工业界的距离

| 环节 | 这个项目 | 工业界 |
|---|---|---|
| 模型 | DeepFM 单模型 | DeepFM / DIN / DCN 等多模型集成 |
| 特征 | 5 个稀疏 + 18 维类型 + 3 个稠密 | 几百到上千个特征 |
| 训练数据 | 285 万条离线 | 几十亿条 + 实时日志 |
| 评估 | 离线 AUC | 离线 AUC + 在线 A/B 测试 |

区别在于工业界特征更多，数据更大，迭代更快。
