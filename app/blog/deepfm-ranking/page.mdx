# 用模型替代手写公式做排序

之前的排序公式长这样：

```text
final_score = 0.5 × 召回分 + 0.3 × 评分 + 0.2 × 热度
```

这三个数字（0.5、0.3、0.2）是我自己定的。一个 18 岁女生和一个 50 岁男人走进来，看到的排序完全相同——公式不认识用户，它只看电影本身的数字。

但现实里推荐应该因人而异。同一批候选电影，年轻女生可能更想看 Forrest Gump，中年男性可能更想看 Godfather。这个"因人而异"靠手写公式写不出来——你没法为每种用户画像 × 每种电影类型手动定一个权重。排列组合太多了。

解决办法：让机器自己看数据去学。给它 285 万条"某个用户喜不喜欢某部电影"的记录，让它自己找出规律。学完之后，输入（用户信息 + 电影信息），它能输出一个预测分——这个用户喜欢这部电影的概率。

这就是模型排序在做的事。下面是具体实现。

---

## 手写公式的局限

之前的排序公式：

```text
final_score = 0.5 × 召回分 + 0.3 × 电影评分 + 0.2 × 热度
```

三个问题：

1. **权重是拍脑袋定的**。为什么召回分占 0.5 不是 0.6？没有依据。
2. **只用了三个信号**。用户的性别、年龄、职业都没用上，电影的类型、年份也没用上。
3. **对所有用户都一样**。一个 18 岁女生和一个 50 岁男人，看到的排序完全相同——只要候选集一样。

模型排序要解决的就是这三个问题。

---

## 模型需要什么：训练数据

模型是从例子里学的。它需要大量的"这个用户喜不喜欢这部电影"的记录。

**正样本**（label = 1）：用户确实喜欢。从评分 ≥ 8 的记录里取。

```text
用户1 + 《飞越疯人院》 → 1（打了 10 分）
用户1 + 《虫虫危机》   → 1（打了 10 分）
```

**负样本**（label = 0）：用户大概率不喜欢。从用户没看过的电影里随机抽。

```text
用户1 + 《某恐怖片》   → 0（根本没看过）
用户1 + 《某爱情片》   → 0（根本没看过）
```

为什么要负样本：如果只给模型看"喜欢"的例子，它会觉得所有电影都好。必须同时告诉它"这些不好"，才能学会区分。

最终训练集：57 万条正样本 + 228 万条负样本 = 285 万条。

---

## 模型的输入和输出

**输入**：关于（用户，电影）这一对的所有信息。

```text
用户侧：user_id、性别、年龄段、职业
电影侧：movie_id、类型（动画/剧情/犯罪...）、平均评分、评分人数
```

**输出**：一个 0~1 之间的数字，表示"预测这个用户喜欢这部电影的概率"。

推理时，模型对候选集里的每部电影打分，按分数从高到低排。

---

## DeepFM：怎么从特征里学出偏好

DeepFM 内部有两条并行的路径：

### FM 路径：看特征的"配对效应"

自动学习所有特征两两之间的关系：

```text
"Under 18 女性" × "动画片" → 加分
"56+ 男性" × "战争片"      → 加分
"25-34 男性" × "爱情片"    → 不加分
```

它不需要你手动告诉它"年轻女性喜欢动画"——模型从 285 万条数据里自己发现这个规律。如果训练数据里 Under 18 女性看动画片的正样本特别多，模型就学到了这个配对的权重应该高。

### DNN 路径：看更复杂的组合

FM 只看两两配对。DNN 能捕捉三个、四个特征一起出现时的效应：

```text
"Under 18 女性" + "动画片" + "高评分" + "90年代" → 很高分
同样的用户 + "动画片" + "低评分" + "60年代"      → 一般
```

DNN 就是几层全连接神经网络，把所有特征拼在一起过几轮非线性变换，能学到更深层的组合关系。

两条路径的输出加在一起，就是最终预测。

## 训练过程

数据划分：

```text
总共 285 万条样本
  ├─ 训练集 80%（228 万条）→ 模型从这里学
  ├─ 验证集 10%（28 万条） → 每轮结束后检测"学得怎么样了"
  └─ 测试集 10%（28 万条） → 训练完之后做最终考试，完全没见过
```

训练用 early stopping（早停）：不预设跑多少轮，而是监控验证集 AUC——连续 3 轮不涨就停。让模型自己决定什么时候该学完了。

实际跑了 30 轮，每轮 18 秒（M 系列 Mac GPU 加速）：

```text
Epoch  1 │ AUC 0.80 ★  ← 刚开始，比瞎猜（0.5）好不少了
Epoch  5 │ AUC 0.89 ★  ← 快速上涨期
Epoch 10 │ AUC 0.92 ★  ← 如果之前只跑 10 轮就停在这了
Epoch 20 │ AUC 0.94 ★  ← 还在涨，但涨幅越来越小
Epoch 28 │ AUC 0.9457 ★
Epoch 29 │ AUC 0.9457    ← 第一次没涨
Epoch 30 │ AUC 0.9458 ★  ← 又微涨了一点点，到上限了
```

最终测试集 AUC：0.9451。和验证集（0.9458）非常接近，说明模型学到的能力是真实的，没有"背答案"。

AUC 0.9451 的含义：随机拿一部用户喜欢的电影和一部不喜欢的，模型有 94.5% 的概率正确判断哪个分更高。

---

## 什么时候会"跌"

这次训练里 AUC 一直在涨（虽然后期每轮只涨 0.0001），没有触发早停。但如果模型更复杂、数据更少，就会出现过拟合——验证集 AUC 开始下降：

```text
Epoch 28 │ AUC 0.9457 ★
Epoch 29 │ AUC 0.9453   （已 1 轮没涨）
Epoch 30 │ AUC 0.9448   （已 2 轮没涨）← 在跌了，模型开始"背答案"
Epoch 31 │ AUC 0.9441   （已 3 轮没涨）← 触发早停！
```

"背答案"就是：模型把训练集里的特殊情况记住了（比如"用户 3827 喜欢电影 1459"），但这些特殊记忆不能推广到新数据上。early stopping 的作用就是在模型开始背答案之前及时刹车，保存还没背答案时的版本。

## 效果对比

同一个用户（用户 1，Under 18 女性），同样的候选集：

```text
手写公式排序：
  1. Shawshank Redemption     [itemcf+popular+vector]
  2. Raiders of the Lost Ark  [itemcf+popular]
  3. Silence of the Lambs     [itemcf+popular]
  4. Star Wars V              [genre+itemcf]
  5. Lion King                [genre+itemcf+vector]

DeepFM 模型排序：
  1. Shawshank Redemption     [itemcf+popular+vector]
  2. Forrest Gump             [itemcf]
  3. Pulp Fiction             [itemcf]
  4. Matrix                   [itemcf]
  5. Godfather                [itemcf+popular]
```

关键差异：

- **Forrest Gump** 从第 14 名跳到第 2 名。模型发现这类用户偏好暖、感人、容易共情的片子。
- **Raiders of the Lost Ark** 从第 2 掉到第 6 之后。手写公式把它排高纯粹因为它被多路召回命中，但模型认为它跟这个用户的匹配度没那么高。
- **Lion King** 从第 5 掉到第 9。虽然三路命中，但模型学到更精细的判断。

核心区别：**手写公式对所有用户排序一样，模型对不同用户给出不同排序**。

## 代码结构

```text
recommender/
  model/
    deepfm.py          # DeepFM 网络定义（PyTorch）
  ranker.py            # 改造：支持模型打分，手写公式作为 fallback
scripts/
  build_train_data.py  # 构造正负样本 + 特征编码
  train_deepfm.py      # 训练模型
data/processed/
  train_data.pkl       # 训练数据
  deepfm_model.pt      # 训练好的模型权重
  deepfm_config.pkl    # 模型配置
```

接口没变——前端调的还是 `GET /recommendations?user_id=1`，后端自动判断有没有模型文件，有就用模型排序，没有就 fallback 到手写公式。

## 训练好之后模型是固定的吗

是的。训练完之后参数就冻住了，保存成一个 942KB 的文件，线上只读取不修改。

这意味着：新用户注册了模型不认识，用户口味变了模型也不知道。它记住的是训练那一刻的数据分布。

工业界的做法：

```text
定期重训：每天/每周用最新数据重新跑一次训练
增量训练：只用最近 N 天的新数据更新参数，不用全量重跑
在线学习：每收到一条新行为就微调一次，实时更新
```

这个项目是最简单的情况——离线训练一次，用到下次重新跑为止。

## 和工业界的距离

| 环节 | 这个项目 | 工业界 |
|---|---|---|
| 模型 | DeepFM（单模型） | DeepFM / DIN / DCN 等多个模型集成 |
| 特征 | 5 个稀疏 + 18 维类型 + 3 个稠密 | 几百到上千个特征 |
| 训练数据 | 285 万条离线 | 几十亿条 + 实时日志 |
| 训练方式 | 全量离线训练 | 增量训练 + 在线学习 |
| 评估 | 离线 AUC | 离线 AUC + 在线 A/B 测试 |

结构一样。区别在于工业界的特征更多（用户最近 5 分钟看了什么、当前时间、设备类型...）、数据更大、迭代更快。
