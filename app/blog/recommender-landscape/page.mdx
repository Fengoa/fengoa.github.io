# 推荐系统全景图

<SeriesNav series="recsys" />

从零做到 V9，算法主线走完了，工程化也做了。回头看整个推荐系统在工业界到底长什么样——不是我们这个 3000 部电影的练手版本，而是抖音、淘宝、Netflix 那种亿级物品库的全链路架构。

下面这张图覆盖了数据层到评估体系的 7 个环节。正体是成熟技术，紫色斜体是 LLM/多模态方向的前沿探索。

## 这张图怎么看

从上往下是一次推荐请求的数据流向。每一层把候选集缩小一个数量级：

**数据层**：所有能用的信号。用户行为是最核心的，但上下文（时间、设备）和社交关系也很有价值。

**特征工程层**：把原始数据变成模型能吃的特征。这一层的工作量往往占整个项目的 60%。

**召回层**：从亿级物品库里快速筛出千级候选。多路并行，每路用不同的信号源。

**排序层**：粗排快速过一遍砍到百级，精排用重模型逐个打分排到十级。

**重排层**：列表级优化。去偏、打散、上下文感知。

**业务策略层**：多样性、冷启动、探索与利用、运营干预。

**评估体系**：离线指标只是起点，在线 A/B 才是终点。工程指标（延迟、QPS）决定了方案能不能上线。

---

## 我们做了哪些

对照这张图，V1-V9 覆盖了：

| 层 | 做了 | 没做 |
|---|---|---|
| 数据层 | 评分、用户画像、电影属性 | 实时行为流、社交图谱 |
| 特征工程 | Hard Negative 采样、Embedding 预计算 | Feature Store、实时特征 |
| 召回层 | 热门/类型/ItemCF/SVD向量/双塔 | 图召回、序列召回、多模态 |
| 排序层 | DeepFM + DIN + MMoE | 粗排（直接跳过了）、LLM 排序 |
| 重排层 | MMR + 类型打散 + 新鲜度 | PRM、因果去偏 |
| 业务策略 | 强插接口 | 冷启动、Bandit 探索 |
| 评估 | HitRate/NDCG/Coverage/AUC | 在线 A/B、工程指标 |

核心链路走通了。缺的部分要么需要更大的数据规模（图召回、实时特征），要么需要线上环境（A/B 测试、Bandit）。

---

## 前沿方向

图中紫色斜体的部分是 2024-2025 年的新趋势：

**LLM + 推荐**：用大模型做冷启动（没有行为数据时靠语义理解）、做召回（把查询和物品都编码成语义向量）、做排序（当作 listwise 排序器）。目前主要问题是延迟太高，很难满足 50ms 的在线要求。

**多模态**：商品有图片、视频、文字描述。用 CLIP 把它们编码成统一向量做跨模态召回。抖音的推荐很大程度依赖视频内容理解。

**因果推断**：传统模型从历史数据学，历史数据有曝光偏差（只能学到"被推过的"）。因果推断用反事实推理去纠正这个偏差。

这些方向还在实验阶段，但 3-5 年内大概率会变成标配。
