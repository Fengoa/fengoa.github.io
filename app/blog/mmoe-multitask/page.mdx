# 多目标排序：一个模型同时优化多件事

<SeriesNav series="recsys" />

之前的 DIN 只优化一个目标：用户会不会给高分。

但实际业务里平台关心很多件事。抖音要同时优化完播率、点赞率、关注率。淘宝要同时优化点击率、加购率、成交率。只优化一个会出问题：只优化点击率推出来全是标题党，只优化好评率推出来全是老经典没有新东西。

MovieLens 没有点击和完播数据，但可以用评分拆出三个层级：

```text
目标 1：用户会不会看这部电影（有评分记录 = 看了）
目标 2：看了之后评分是否 ≥ 6（及格）
目标 3：评分是否 ≥ 8（高分）
```

这三个目标有递进关系：看了 → 及格 → 高分。和真实业务的"点了 → 看完 → 好评"逻辑一致。

---

## MMoE 的结构

MMoE（Multi-gate Mixture-of-Experts）的思路：多个目标共享底层的特征提取网络（Expert），每个目标有自己的门控网络（Gate）来决定用哪些 Expert 的输出。

```text
输入特征（用户 + 电影 + 行为序列）
       │
  ┌────┼────┐
Expert1 Expert2 Expert3     ← 3 个共享的特征提取网络
  │    │    │
  ├────┼────┤
Gate1  Gate2  Gate3         ← 每个目标一个 Gate，各选自己的组合
  │    │    │
Tower1 Tower2 Tower3        ← 每个目标一个输出头
  │    │    │
P(看了) P(及格) P(高分)
```

Gate 让不同目标能侧重不同的特征模式。"会不会看"可能更看电影热度和标题吸引力，"评分高不高"可能更看口味匹配度。Gate 自动学出这种分工，不需要人为指定。

## 训练

三个目标的 BCE loss 加权求和：

```text
总 loss = 0.3 × loss(看了) + 0.3 × loss(及格) + 0.4 × loss(高分)
```

训练 14 轮触发早停，每轮 5 秒：

```text
Epoch  1 │ 看了 0.77 │ 及格 0.76 │ 高分 0.76
Epoch  5 │ 看了 0.88 │ 及格 0.87 │ 高分 0.85
Epoch 10 │ 看了 0.92 │ 及格 0.90 │ 高分 0.88
Epoch 14 │ 看了 0.93 │ 及格 0.91 │ 高分 0.89 ★ 最佳
Epoch 17 │ 早停
```

测试集结果：

```text
目标       AUC
看了       0.925
及格       0.908
高分       0.887
```

三个目标都学到了。"看了"最容易预测（AUC 最高），"高分"最难。

## 多目标的实际用法

训练完之后模型对每部候选电影输出三个概率。最终排序分按业务权重加权：

```text
方案 A（优化点击率）：final = P(看了)
方案 B（优化好评率）：final = P(高分)
方案 C（平衡）：     final = 0.3×P(看了) + 0.3×P(及格) + 0.4×P(高分)
```

换权重不需要重新训练，直接改系数就行。产品经理说"最近用户留存下降了，多推高质量内容"，把 P(高分) 的权重调大就可以。

## 和 DIN 的关系

MMoE 和 DIN 解决的是不同层面的问题：

DIN 解决的是"用什么信号打分"（加入行为序列）。MMoE 解决的是"优化什么目标"（同时预测多个指标）。

两者可以结合。把 DIN 的 attention 机制放进 MMoE 的 Expert 里，就能同时做序列建模 + 多目标优化。工业界大部分排序模型都是这样组合的。

## 和工业界的距离

| 环节 | 这个项目 | 工业界 |
|---|---|---|
| 目标数 | 3 个 | 5-10 个（点击/观看/完播/点赞/评论/分享/关注...） |
| Expert 数 | 3 个 | 8-16 个 |
| 架构 | MMoE | PLE（Progressive Layered Extraction，腾讯改进版，Expert 不完全共享） |
| 权重调整 | 手动设系数 | 在线 A/B 测试 + 自动调权 |

工业界从 MMoE 演化出了 PLE（让不同目标有各自的私有 Expert，不完全共享），和 ESMM（用目标之间的因果关系做约束，比如"点击"是"购买"的前提）。
