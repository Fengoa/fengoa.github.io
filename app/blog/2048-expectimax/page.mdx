# 给 2048 写一个 Expectimax bot

站上的 [2048 Arena](/2048) 允许你粘贴一段 JavaScript，让程序自己推盘、认领站点后进赛周榜。仓库里另有一份控制台脚本 `scripts/2048-ai-console.js`，面向「任意网页读盘 + 派发方向键」的场景。两者搜索核相同：行查表启发式加 Expectimax，再加迭代加深。

这篇文章把这条链路拆开写清楚：为什么搜索树要分成 Max 与 Chance、一行局面怎样压进 16 位、叶节点四项启发各自对应棋盘上的什么现象、时间不够时迭代加深怎么取舍，以及挂到带动画的 Arena 时要多等什么。文末附上已适配 Arena 编辑器的完整脚本，可直接复制去 [/2048](/2048) 冲榜。

封面里那块奶油色棋盘在自动落子，用的是同一套局面编码下的轻量启发，方便一眼看到节奏。冲分请用文末那份完整搜索。

## 先看一步决策在算什么

假设当前盘面左上角有两个相邻的 `2`，其余大多为空。人会立刻想到「向左或向上合并」。程序若只会随机方向，平均分上不去；若只看「这一步立刻得分」，又容易把大块推到中间，后面几步把盘面走死。

Expectimax 的做法是：对每个合法方向，想象走完之后环境会在某个空格放 `2` 或 `4`，再对每种可能继续往下想几步，最后用启发式给「想不动了」的叶节点打分，再按概率把这些分加权平均回来。根节点选期望分最高的那个方向。

深度为 1 时，它几乎就是「走完一步 + 对新盘面做启发评估」。深度加到 3、4 之后，会开始提前躲开「看起来能合并、两步后却被堵死」的陷阱。浏览器里每步只有一两百毫秒，所以深度不能盲目拉满，这是后文迭代加深要解决的问题。

## 搜索树为什么长成 Expectimax

走完一步之后，空格里会出现新块：大约 90% 是 `2`，大约 10% 是 `4`，位置在空格上均匀分布。搜索树因此交替出现两类节点。

**Max 节点**轮到你：在 `up / down / left / right` 里选一个合法方向，目标是让后续局面的期望收益尽量高。

**Chance 节点**轮到环境：对「每个空格 × 两种新生面值」按概率求平均。空格有 <Math>{`n`}</Math> 个时，某个具体「在格子 i 放 2」的概率是 <Math>{`(1/n)\\times 0.9`}</Math>。

Minimax 假设对手总选对你最不利的一手。2048 的环境按固定分布抽样，把最坏情况换成按概率加权的期望，就是 Expectimax：

<Math block>{`V_{\\max}(s) = \\max_{a} V_{\\mathrm{chance}}(s, a)`}</Math>

<Math block>{`V_{\\mathrm{chance}}(s, a) = \\sum_{s'} P(s'|s,a)\\, V_{\\max}(s')`}</Math>

展开到深度上限后，用启发式 <Math>{`H(s)`}</Math> 给叶节点打分。整棵树回答的问题很具体：从当前盘面再往下走，期望能进入多整齐、多有空位的局面。

实现里还会用概率剪枝：当某条分支到达叶节点前，累计概率已经低于阈值（脚本里是 `0.0001`），就提前用 <Math>{`H(s)`}</Math> 收束，把时间留给更可能发生的变化。

## 把一行压成 16 位

递归里如果每次都扫描 16 格、现场压缩一行，节点一多就会很慢。常见做法是把**每一行**编成一个 16 位整数：四个格子各占 4 bit，存的是面值的阶 <Math>{`\\log_2(v)`}</Math>（空格为 0，2 为 1，4 为 2，8 为 3，……）。整盘用四个 `uint16` 表示，也就是长度为 4 的整数数组。

本仓库脚本的位序是：行内第 0 列占最低 4 bit，第 3 列占最高 4 bit。例如一行格子面值 `[2, 2, 0, 4]`，对应阶 `[1, 1, 0, 2]`，打包后为：

<Math block>{`1 \\mid 1 \\mid 0 \\mid 2 \\quad\\Rightarrow\\quad \\texttt{0x2101}`}</Math>

（从低 nibble 往高写：`1 + (1<<4) + (0<<8) + (2<<12)`。）

启动时预计算全部 65536 种行状态，填进几张表：`MOVE_LEFT` / `MOVE_RIGHT`（滑动合并后的新行）、`MOVE_SCORE`（该行合并得分）、`EMPTY_COUNT`、以及后面启发式要用的 `HEUR`。竖着推时先把四行转置成四列，再复用同一张行表，最后转置回去。一次移动主要变成几次查表和位运算，Expectimax 才有机会在浏览器里每步展开足够多的节点。

`encodeGrid` 负责把 Arena 传来的 `number[][]`（真实面值）转成这四个整数；`chooseMove` 搜完后再把方向名 `'up'|'down'|'left'|'right'` 交回 runner。

## 叶节点在估什么

叶节点分是四行加四列、一共八次查表之和。单行可以粗略写成：

<Math block>{`H_{\\mathrm{row}} = C_{\\mathrm{lost}} + w_e E + w_m M - w_{\\mathrm{mono}}\\min(L,R) - w_s S`}</Math>

各项对应的棋盘现象如下。

**空格 <Math>{`E`}</Math>**（权重 270）。空位多，后面更不容易被堵死，也给随机新块留下缓冲。开局这项往往主导短期选择。

**可合并对 <Math>{`M`}</Math>**（权重 700）。相邻同阶块越多，短期能加分，盘面也更容易收拢。权重最高，说明「能合就合」在启发式里很强；真正的深度搜索会在后面几步修正「合完却破坏单调坡」的情况。

**单调性 <Math>{`L/R`}</Math>**（权重 47）。分别累计两个方向上「高阶在左 / 高阶在右」的不顺程度，再取较小者惩罚。效果是鼓励大块靠一侧、小块顺坡排布，减轻高阶块被夹在中间、两边都合不出去的局面。

**面值和 <Math>{`S`}</Math>**（权重 11，阶的 3.5 次幂和）。抑制「一堆中等块挤在一起、却合不出去」的板结：同样多的材料，摊成许多中等阶，比收成少数高阶更吃亏。

常数 <Math>{`C_{\\mathrm{lost}}`}</Math> 是一个很大的正偏置，方便和「无合法着」等极端情况比较。上述系数来自公开的 CMA-ES 调参结果，出处是 [nneonneo/2048-ai](https://github.com/nneonneo/2048-ai)。

这套 <Math>{`H`}</Math> 是工程近似。它和一定深度的 Expectimax 叠在一起时，固定深度 4 的自对弈里经常能看到十万量级的总分；更深、更长的思考时限通常还能抬高 8192、16384 的出现率。具体数字随随机种子波动，不宜当成保证值。

## 时间不够时：迭代加深

浏览器里按固定深度死算不现实。有的局面空格多、Chance 分支大；有的残局空格少，同样毫秒数能搜得更深。控制台与 Arena 脚本都用**迭代加深**：

从较浅的完整深度起（常见从 3 或 4 开始，视空格数与不同面值种类微调），在时限内一层层往上加。某一层四个方向都搜完，才采纳该层的最佳着；超时则退回上一层已经完整比完的结果。半截根节点评估丢弃不用，避免「只搜完两个方向就下结论」。

开局空格多时，先保证浅层搜完；盘面拥挤、分支变窄后，起始深度可以抬高一点。置换表按当前深度上限缓存 Chance 节点估值，**换深度时清空**，避免浅层结果污染深层。根节点还会按启发分给合法方向排个序，让看起来更好的着法更早被完整评估，时限触顶时手里至少还有一个已经比完的候选。

日志或调试里若打印「深度 12」，在强概率剪枝下也不等于真的展开了 12 层完整树，读的时候需要留一点余地。Arena 适配版默认 `THINK_MS = 150`；冲分可以把开头常量改成 `200`～`350` 再跑。

## 接到 Arena：动画比算法更先卡住你

算法对了，挂到有滑动动画的页面上仍可能分数上不去。Arena 的滑动大约 180ms，合并弹动更长。若按键间隔压到几十毫秒，大量输入会在动画锁定期被丢掉，bot 等于拿着过期棋盘做决策。

控制台脚本因此自己读 DOM、等棋盘指纹稳定再思考。Arena 编辑器则简单得多：你只导出 `chooseMove(board)`，runner 负责 `api.move(dir)` 并等待动画结束，再把新的 `board` 交给下一步。适配版删掉了读盘与派发按键，只保留搜索核与 `chooseMove`。

读盘若自己做，还要避开动画中帧：合并过程中两块会短暂叠在同一格，若用 `Math.max` 合并数值，会少算一块。比较稳妥的流程是：棋盘稳定 → 思考 → 发一次方向 → 等到局面指纹变化并再次稳定 → 再进入下一步。

## Arena 接口约定

编辑器里的脚本在隔离函数中执行。你可以提供二者之一。

`chooseMove(board)`：同步函数，`board` 为 `number[4][4]`，`0` 表示空格，返回 `'up'|'down'|'left'|'right'`，无着可返回 `null`。Runner 会循环调用，并在两次调用之间等动画。

`async function play(api)`：自行驱动循环。`api.board()`、`api.score()`、`api.over()`、`api.move(dir)`、`api.sleep(ms)`、`api.log(...)` 可用。文末脚本走的是 `chooseMove` 路径，接入成本更低。

## 这套脚本停在哪里

学术路线上还有 N-tuple 网络加 TD-afterstate、多阶段 TD 等，公开结果可以把平均分再抬一截，权重大、训练成本也高，不适合整段粘进浏览器编辑器。当前脚本刻意停在「行查表启发 + Expectimax + 迭代加深」：单文件、步骤可跟读，在现代浏览器里可以实时演示并用于 Arena 冲榜。

若你改启发权重或加深时限，建议先在本机用 `--bench` 看平均分与最大块分布，再拿到 [/2048](/2048) 上跑赛周榜，避免只凭一两局手感下结论。
