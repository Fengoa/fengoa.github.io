# 训练：让模型学会说话

<SeriesNav series="llm" />

前四篇把 Transformer 拼齐了。本篇聚焦训练流程：将模型从随机输出训练为可续写莎士比亚台词的语言模型。

模型放大至 4 层、256 维、4.17M 参数，tokenizer 换用 BPE-4000，上下文扩展至 128 token，在 Tiny Shakespeare 上训练 10000 步，单卡耗时 17 分钟。val loss 于训练中途开始反弹，属典型过拟合。后续讨论均围绕该现象展开。

<GenerationEvolutionSlider />

## 训练配置

模型 4 层、256 维、8 头，总参数 4.17M。优化器为 AdamW，β1=0.9、β2=0.95、weight_decay=0.1。学习率 200 步线性 warmup 至 3e-4，之后 cosine 衰减至 3e-5。共 10000 步，Mac M 系列单 GPU 耗时 17 分钟。

数据是 BPE-4000 编码的 Tiny Shakespeare，267K token，上下文 128 个 token，约 480 个字符。比上一篇 64 字符的窗口大了七倍，模型终于能看到整段台词的前后文。

## Loss 曲线形态

train loss 一路从 8.35（接近 ln 4000）滑到 0.46，几乎完美。val loss 却在 step 1500 见底于 5.77，之后开始往回涨，到 step 10000 已经爬到 7.9。把两条线画在一起，故事一目了然。

<LossCurveChart />

train 一直在降、val 先降后升，这就是过拟合最经典的形状。模型在背训练集——4.17M 参数面对 267K token，参数比 token 还多 15 倍，模型有的是容量把整本书记下来。

代价不是看起来“loss 高一点”那么轻巧。Chinchilla 给了一个粗略的经验比例：

<Math block>{`\\frac{D}{N} \\approx 20 \\quad \\text{即 每个参数大约消化 20 个 token}`}</Math>

我们的比值是 0.06，差了三个数量级。

## 过拟合时生成质量在哪里见顶

有一个反直觉的细节值得留意：**val loss 从 step 1500 就开始恶化，但人眼看到的生成质量在 step 6000 左右才达到峰值**。

step 2000 的续写还在编单词（"subbeny"、"stified"），到 step 6000 已经能写出格式正确、语法通顺的对话；继续训练到 step 10000，文字更像莎翁，但很多片段是直接从训练集里抄出来的。模型一边复述原文，一边补全那些它没完整记住的格式细节，所以人眼觉得「还在变好」。

这是一个有意思的提醒：val loss 的最低点和「生成主观最佳」的点可以错开几千步。若目标是数学正确的泛化能力，以 val loss 为准；若目标是拿出一个像样的 demo，可以多生成几个 checkpoint 自行挑选。

正确的工程做法仍然是 early stopping：在 val loss 连续 N 步不降时停下，把那个最佳 checkpoint 拿去用。在我们这次实验里，最佳模型出现在 step 1500（val 5.77），最终模型反而 val=7.9——保留最优 checkpoint 直接给了你 30% 的损失差。

## 训练技巧的真实作用

工业界的训练 loop 看起来很复杂，但去掉框架封装后核心就是四件事：学习率怎么变、梯度怎么裁、权重怎么收紧、输入输出 embedding 共不共享。这一节把它们串起来讲清楚。

学习率上 cosine schedule 是为了解决一个尴尬的开局：刚初始化的参数离最优解很远、梯度方向也不太对，这时候 LR 大了容易把梯度带偏甚至 NaN。所以前 200 步先做 warmup，把 LR 从 0 线性抬到 3e-4，让模型先“找到方向”。后面进入 cosine 衰减，LR 平滑地降到 3e-5，避免在最优点附近来回震荡，也方便最后阶段精调。

<LRSchedulePlot />

梯度裁剪解决的是另一个问题：偶尔会撞到一个特别“难”的样本，单步梯度爆炸式增大，更新一下整组权重直接歪掉。常用做法是把整批梯度的 L2 范数限制在 1.0 以内：

<Math block>{`g \\leftarrow g \\cdot \\min\\Big(1, \\dfrac{1.0}{\\lVert g \\rVert_2}\\Big)`}</Math>

代码上一行 `torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)` 就够了。

Weight decay 和 LR schedule 配合使用，每一步把权重往 0 拉一点点（AdamW 的实现里它和优化器解耦，所以不会被自适应学习率稀释）。在我们这种数据严重不足的场景下它帮助有限，但在真实大模型里它和 dropout 一起负责把权重数值范围压住，避免某一层参数飘出几百倍。

最后一个是 weight tying：让 token embedding 和 lm_head 共享同一组权重。输入端「king 的向量表示」与输出端「预测 king 的分布」对应同一语义空间。共享后省去一份 vocab × embed_dim 的参数（此处为 4000 × 256 = 1M，约占总参数 1/4），训练也更稳定。

## 数据不够，模型再优秀也救不了

回到最开头 0.06 的比值。两条出路均成立：将模型缩至 13K 参数（容量过小，难以学到有效模式），或将数据扩至 80M token（超出 Tiny Shakespeare 总量）。教学项目中选择接受过拟合，通过 early stopping 获取可用 checkpoint。

工业界没有这个烦恼。互联网文本几十 TB，模型再大也不够背，只要数据和算力同步扩大，loss 就持续下降——这正是下一篇 Scaling Law 要展开的主线。

## 代码结构

```text
minimal-llm/src/
  train_full.py    # 正式训练（cosine LR + gradient clip + 大模型）

python train_full.py                            # 默认 17 分钟

python train_full.py --n_layer 2 --n_embd 128   # 缩小模型，配小数据
```

## 和工业界的距离

| 环节 | 这个项目 | GPT-4 级别 |
|------|---------|-----------|
| 数据量 | 267K tokens (1MB) | 几万亿 tokens (几十 TB) |
| 模型 | 4.17M 参数 | 万亿参数 |
| 训练时间 | 17 分钟 / 单卡 | 数月 / 数千 GPU |
| N/D 比值 | 0.06（严重不足） | 接近或超过 Chinchilla |
| LR Schedule | warmup + cosine | 一样 |
| 优化器 | AdamW | 一样 |
| Gradient Clip | 1.0 | 一样 |
| 训练阶段 | 只有预训练 | 预训练 → SFT → RLHF |

技术细节几乎完全一致，差距全在数据规模。这表明训练 LLM 并无「工业秘方」——数据与算力充足时，只需稳定执行已知训练循环。
