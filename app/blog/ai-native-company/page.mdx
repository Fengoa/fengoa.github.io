# AI 原生公司：以目标、能力与实验重构组织


当生产力与人数解绑之后，公司按什么单位来组织？

## 为什么要重看公司组织形式

过去约一百年，公司组织设计默认一条假设：**人是生产力的基本单位**。

职位、部门、管理层、流程与 KPI，都建立在这条假设上。增长路径通常写成两件事：增加员工数量，提高单人效率。规模也习惯用人数衡量——十人、千人、万人——这是工业时代留下的度量。

AI 正在改写这条前提。小团队配合模型与工具，已能覆盖市场研究、内容生产、软件开发、客户支持、数据分析、销售触达等过去需要更大编制才能完成的工作。

于是问题变成：**若产出不再随人数近似线性扩展，组织应以何种单位重新设计？**

「AI-native Company」（AI 原生公司）讨论的，正是这一层。

## 传统公司的瓶颈在协调

一千人规模的公司，常见链条是：CEO → VP → Director → Manager → Employee。决策沿链下传，信息逐级损耗，响应变慢，部门之间形成壁垒，同类工作被重复。编制扩大后，管理开销往往同步上升。

以营销需求为例，传统链路常是：提出目标 → 市场制定计划 → 内容写方案 → 设计出素材 → 投放 → 数据分析 → 复盘。走完一轮，经常以周计。

真正紧缺的，是一套能理解目标、拆解问题、并根据结果持续调整的**智能协调系统**。

## OpenAI 与 Anthropic 提供了哪些线索

一种常见想象是「CEO + 一百个 AI 员工」。公开资料呈现的是另一种形态：人和汇报线仍然存在，但工作更频繁地围绕目标组成跨职能小队。

### OpenAI：共享平台与端到端产品小队

OpenAI 的 ChatGPT 负责人 Sulman Choudhry 在[公开访谈](https://sfelc.com/podcasts/how-openais-engineering-org-is-reshaping-teams-roles-and-workflows-sulman-choudhry-openai)中介绍过两类团队：

- **水平团队（horizontal）**：建设训练、推理、实时语音等共享基础设施
- **垂直团队（vertical）**：围绕 ChatGPT 体验、用户场景与产品指标推进

垂直团队通常包含研究、工程、产品与设计，并由一名 **DRI（Directly Responsible Individual）** 对端到端结果负责。模型能力从研究进入产品时，无须依次移交给多个孤立部门；同一小队可以完成实验、工程实现、体验验证与发布。

### Anthropic：研究问题域与 Claude 交付链并行

Anthropic 的[官方研究页面](https://www.anthropic.com/research)列出 Alignment、Interpretability、Societal Impacts、Frontier Red Team、Economic Research 等研究团队。这些团队按问题域研究模型行为、安全边界与社会影响。

Claude.ai 与 Claude API 仍由产品、应用工程、基础设施、政策与商业化能力共同交付。研究侧产出训练与安全方法，产品和工程将模型接入对话、工具调用与企业场景，评测结果再返回训练与产品决策。

两家公司没有公开一套可直接复制的「AI 原生组织架构」。公开信息能够支持的结论更克制：**目标可以成为跨职能协作的一级索引，能力围绕目标组合，实验结果决定下一轮资源分配。**

## 从岗位分工转向目标与能力组合

传统组织通常先按职位分配任务，再由员工交付结果。AI 原生组织先定义目标和成功标准，再根据实验需要组合研究、写作、设计、编程、分析与执行能力。

固定岗位仍然存在，但不再承担全部协调职责。以「提升产品用户量」为例，Research 识别需求，Writing 生产内容，Video 制作素材，Browser 执行运营动作，Analytics 评估结果。每轮实验都可以重新组合这些能力。

## 核心模型：从使命到结果的链路

<CoreOperatingLoop />

图的上半部分是一条从抽象方向到可度量结果的执行链。Mission 规定组织为何存在以及哪些边界不能越过；Goal 把使命转换成某个周期内可验证的结果；Strategy 选择实现目标的路径；Experiment 把路径中的判断改写成可以比较的试验。实验继续拆成 Task，再为任务匹配 Capability，由能力调用 Tool 接触外部系统，最后沉淀为 Result。

下半部分是一条反馈链。Result 进入 Evaluation，与 Goal 和预先定义的指标比较。评估在逻辑上独立于执行过程，不预设具体部门归属。评估结论返回 Strategy 与 Experiment：有效路径获得更多资源，效果有限的实验被终止或调整。使命与目标在单轮执行中保持相对稳定，策略和实验持续变化，因此反馈箭头落在这两层。

---

- **Mission（使命）**：存在理由，例如「帮助一百万人学习 AI」
- **Goal（目标）**：可度量结果，例如「一年达到一百万用户」
- **Strategy（策略）**：实现路径，例如内容增长、社区增长、产品增长
- **Experiment（实验）**：并行试探有效方法的单位。同一增长目标下，可同时试验 Twitter 运营、短视频、SEO、邮件等多条路径
- **Task（任务）**：实验中的最小执行单元，例如生成一篇文章、发布一条内容、采集一组数据
- **Capability（能力）**：完成任务所需的可复用能力，例如研究、写作、设计、编程与分析
- **Tool（工具）**：能力连接外部系统的接口，例如浏览器、代码仓库、邮件、CRM 与内容平台
- **Result（结果）**：任务执行后产生的业务数据与中间产物，例如新增用户数、转化率、内容与实验记录

**Evaluation（评估）** 负责比较结果与目标。若目标是「增加用户」，却用「发布一百条内容」作为 KPI，系统会持续优化内容产量；评估应回到新增用户数、转化率、ROI 等结果指标。评估结论随后调整策略、实验优先级与资源投入，形成下一轮执行。

以「帮助一百万人学习 AI」为例：组织先把阶段 Goal 定为「本季度新增一万名有效学习用户」，Strategy 选择 SEO 内容增长，Experiment 比较「原理长文」与「项目教程」两类内容的获客效果。每个实验拆成选题研究、写作、发布、埋点等 Task；系统调度 Research、Writing、Analytics 等 Capability，并调用搜索数据、内容系统与分析平台等 Tool。最终得到阅读量、注册数、学习完成率和获客成本等 Result。Evaluation 按有效学习用户数与成本判断实验价值，再决定下一轮增加哪类内容的资源权重。

## 闭环积累的组织资产

通用 Agent 与提示词的复制成本较低。目标—实验—评估闭环长期运行后，会积累五类组织资产：

1. **Knowledge（知识）**：产品、用户、市场的专有知识
2. **Memory（记忆）**：组织经验，例如历史实验记录
3. **Capability（能力）**：内容、设计、销售等已组织化的能力模块
4. **Evaluation（评估）**：辨别「什么真正有效」的度量与判断
5. **Experiment History（实验历史）**：做过什么、因何失败的可检索档案

竞争差异最终落在这些资产的质量上：系统是否理解业务背景，是否保留实验历史，是否能判断结果，并把判断转化为下一轮资源分配。

## 理论边界

本文只定义 AI 原生组织的协调逻辑：以目标组织工作，以能力完成任务，以实验和评估形成学习循环。它不描述具体汇报线，也不规定软件模块、数据结构与运行时实现。

部门、岗位与人仍然承担责任、授权和高风险决策。变化发生在协调层：工作从固定岗位表流向目标与能力组合，组织可以更频繁地依据结果重新配置资源。

## 结语

过去常用公式：公司 = 人 × 流程。

更贴近 AI 原生形态的写法是：公司 = **目标 × 能力 × 学习循环**。

工业时代组织人力，互联网时代组织信息流。AI 原生组织进一步管理可调度的智能能力，以及这些能力产生的实验反馈。
