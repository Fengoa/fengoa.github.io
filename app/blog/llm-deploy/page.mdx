# 部署上线

<SeriesNav series="llm" />

模型训完了、压量化完了、推理也优化过了，但这些都是单机能跑起来的事。要让它真正服务用户，得包成一个 HTTP 服务——别人发个请求，几秒钟拿到回答。这一篇就讲这件事怎么做。

整套流程和推荐系统工程化那篇思路完全一样：把「能跑」变成「能用」。挑框架、起服务、做 streaming、上 Docker、做监控、算账。重要的不是哪个工具最炫，而是搭出来的东西稳定、便宜、好换。

## 推理框架挑哪个

vLLM、TGI、llama.cpp、Ollama，名字都听过。它们各自的位置其实很清楚——做生产服务首选 vLLM 或 TGI，本地玩或者部署到边缘设备就走 llama.cpp 系。Ollama 是 llama.cpp 的傻瓜壳，命令行 `ollama run llama3` 就能起来，开发机上调试很省心。

<InferenceFrameworkRadar />

雷达图把这件事画得直观：vLLM 在吞吐和生态上最强，代价是配置略多；llama.cpp 极省资源、量化方案最齐，但单卡吞吐打不过 vLLM；Ollama 用起来最舒服，但生产场景吃不消。

## vLLM 起服务

工业界生产线上 90% 跑 vLLM。安装、起服务、调用，三件事加起来三行：

```bash
pip install vllm
vllm serve meta-llama/Llama-3-8B-Instruct \
  --quantization awq \
  --max-model-len 4096 \
  --port 8000
```

启起来之后就是一个 OpenAI 兼容的 HTTP 服务。客户端代码完全不用改，把 `base_url` 从 `api.openai.com` 换成 `localhost:8000` 就行：

```python
from openai import OpenAI

client = OpenAI(base_url="http://localhost:8000/v1", api_key="dummy")
response = client.chat.completions.create(
    model="meta-llama/Llama-3-8B-Instruct",
    messages=[{"role": "user", "content": "What is 2+2?"}],
    stream=True,
)
for chunk in response:
    print(chunk.choices[0].delta.content, end="", flush=True)
```

这种 OpenAI 协议的兼容性是有意义的。Cursor、Continue、LangChain、各种 SDK 都默认走这套接口，自己的服务做成兼容格式，整个生态的工具链立刻能用上。换模型只是改 `model` 字段，业务代码零改动。

## Streaming 不是花活

用户从输入框点回车到看到第一个字的延迟，叫 TTFT（Time To First Token）。这个数字的体感比总生成时间重要得多。

如果一次请求要生成 200 个 token、每个 token 40 ms，总生成 8 秒。Batch 模式下用户得等满 8 秒才看到回答；Streaming 把每个 token 边生成边推给前端，第一个字 40 ms 就到了，剩下的字慢慢续。同样的总耗时，前者像是卡住了，后者像是有人在打字。

<StreamingVsBatchDemo />

实现方式是 Server-Sent Events（SSE）。服务端每生成一个 token 就 flush 一行 `data: {...}\n\n`，浏览器侧用 EventSource 或 fetch 流式读取。vLLM 默认就开了，前端按 OpenAI 流式协议处理就行。

## Docker 包起来

直接 `pip install` 部署在生产机上不可控——驱动版本、CUDA 版本、Python 包版本任何一个不对都跑不起来。包成 Docker 镜像才是正经做法：

```dockerfile
FROM vllm/vllm-openai:latest
ENV MODEL_NAME=meta-llama/Llama-3-8B-Instruct
CMD ["--model", "${MODEL_NAME}", "--quantization", "awq", "--port", "8000"]
```

加上 docker-compose 把模型权重挂载、GPU 资源声明、端口映射都写清楚：

```yaml
services:
  llm:
    image: vllm/vllm-openai:latest
    ports: ["8000:8000"]
    volumes: ["./models:/models"]
    deploy:
      resources:
        reservations:
          devices: [{capabilities: [gpu]}]
    command: >
      --model /models/llama-3-8b-awq
      --quantization awq
      --max-model-len 4096
```

部署到任意一台带 GPU 的机器，`docker compose up -d` 就能拉起来。换机器、加副本、滚动升级，都是这一套。

## 一个能扩的架构

单机起服务很容易，但单机扛不住任何意义上的"流量"。一台 L4 显卡正常压测大概 10-20 并发请求就饱和了，更多的请求要么排队要么超时。

到底能撑多少并发，不是猜的。粗算一下显存预算就清楚——模型权重 + 每条请求的 KV Cache：

<Math block>{`\\text{VRAM} \\approx P \\cdot b_w + B \\cdot L \\cdot 2 \\cdot n_{\\text{layer}} \\cdot d_{\\text{kv}} \\cdot b_{kv}`}</Math>

`P` 是参数量、`b_w` 是权重每个数占的字节数（FP16 是 2，INT4 是 0.5），后半段 `B · L · ...` 是 batch 大小乘上序列长度、每层 K + V 两份缓存。LLaMA-3-8B AWQ 量化后权重 4 GB，剩下的 20 GB 在 4K context 下大概能塞 20 来个并发——这就是单卡的天花板。

生产架构的最小单元长这样：

<DeploymentArchitectureDiagram />

入口是 Nginx 做 TLS、限流、按 token 鉴权。后端是几个 vLLM 实例，每个跑在一张 GPU 上，模型权重统一放在 S3 或共享 NFS 上。Nginx 把请求轮询分发，某个实例挂了直接摘掉，新实例拉起来从 S3 把权重拉一遍就能上。

监控这块至少得有 Prometheus 抓 vLLM 的 metrics——QPS、TTFT、P99 延迟、KV Cache 占用率、运行中的请求数。Grafana 搭个 dashboard，凌晨三点哪个实例 OOM 了能立刻知道。

业内常用的压测工具是 `wrk` 或 `locust`。一张 L4 跑 LLaMA-3-8B AWQ 量化版本，连续批处理打开，正常能稳定到 200-300 tokens/s 总吞吐，P99 单 token 延迟 60-80 ms。开两副本翻倍，开三副本基本就能覆盖一个中等规模的内部应用。

## 算清楚成本

最绕不开的问题——自部署到底比 OpenAI API 便宜还是贵？答案完全看每月用量。

<CostCalculatorSelfVsApi />

一张 L4 spot 价格大约 \$500/月。GPT-4o 当前定价约 \$2.5 / 1M tokens（输入输出粗合）。在拐点 200M tokens 上下，两边持平。

每月用量在 50M 以下的应用，自部署完全没必要——付 \$500 月租维护一台机器，比 \$125 的 API 账单贵 4 倍，还得自己运维。每月 1B tokens 以上的场景，自部署成本只有 API 的 1/5，规模再大就更悬殊。绝大多数 toC 应用都在前面那个区间，所以即便国内有完整的开源模型选择，多数团队仍然在用 API。

真正适合自部署的场景不外乎几种：数据出不了内网（合规）、调用量已经稳定大到每月数亿 token（成本）、对延迟有严格要求（API 排队不可控）、需要做特定微调（API 不让训）。

## 和工业界的距离

这一篇做出来的东西，是教学版的最小生产架构。真到大厂级别，每一层都要再厚几个数量级。

| 环节 | 这篇做的 | 大厂级别 |
|------|---------|---------|
| 框架 | 单台 vLLM | vLLM + Kubernetes 自动扩缩容 |
| 负载均衡 | Nginx | Envoy + 一致性哈希做 KV Cache 复用 |
| 监控 | /health + Prometheus | 全链路 tracing + 异常自动告警 |
| 模型管理 | 手动换 image tag | A/B 测试 + 灰度发布 + canary |
| 安全 | API Key | 内容审核 + Rate Limit + 用量配额 |
| 成本 | 单卡 \$500/月 | 数千卡 \$几百万/月 + 容量预测 |
