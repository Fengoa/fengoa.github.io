# 从零搭一个语言模型

<SeriesNav series="llm" />

在 ChatGPT 里输入"帮我写一首七言绝句"，两秒钟之后它就给你写好一首。这件事到底是怎么发生的？

说穿了，背后就一件事：给定前面的字，预测下一个字。"床前"后面大概率是"明月"，"明月"后面大概率是"光"。当一个模型把这件事预测得足够准，它就是 GPT。

这篇文章会从最简单的模型开始，一步步搭到能写出几句莎士比亚风格台词的 mini Transformer。一共三个模型，用的都是同一份数据。

---

## 语言模型在做什么

写成数学只有一行：

<Math block>{`P(\\text{next} \\mid \\text{context})`}</Math>

给定一段前文，模型输出下一个 token 在词表上的概率分布。token 的粒度可以很灵活，可以是单个字母，也可以是 "ing" 这样的片段，或者干脆是一个完整的词。这篇文章用最简单的字符级方案，每个字母、标点和换行都算作一个 token。

<NextTokenPrediction />

模型要学的就是这个分布。前文看得越多，分布估得越准，生成出来的文本也就越通顺。

---

## 数据

数据用 [Tiny Shakespeare](https://raw.githubusercontent.com/karpathy/char-rnn/master/data/tinyshakespeare/input.txt)，是从莎士比亚全集里截取的一段文本，大小 1MB，约 100 万字符。

整个文件里只出现了 65 种不同字符，包括大小写字母、常见标点、空格和换行。所以词表大小 `vocab_size = 65`，模型在生成时只需要在这 65 个字符里做选择。

数据长这样：

```text
First Citizen:
Before we proceed any further, hear me speak.

All:
Speak, speak.

First Citizen:
You are all resolved rather to die than to famish?
```

通篇都是"角色名 + 冒号 + 台词"的格式，结构非常规整。模型如果学到位了，生成出来的文本也应该是这个样子。

把文本喂给模型之前，要先把字符变成数字。给 65 个字符各编一个号（0 到 64），把整个文件按这张表查一遍，`"Hello"` 就成了 `[20, 43, 50, 50, 53]`。前 90% 用来训练，后 10% 留作验证。最后存成二进制文件，下次加载更快。

## 模型 1：Bigram，只看前一个字符

最简单的做法：只看当前字符，预测下一个。

```text
看到 'H' → 下一个大概率是 'e'（He/His/Her...）
看到 'q' → 下一个大概率是 'u'（qu- 组合）
看到 ':' → 下一个大概率是换行（台词开始）
```

实现上就是一张 65×65 的查找表，第 i 行存的是"当前字符是 i 时，下一个字符的概率分布"。模型要做的，就是把这 4225 个数字调到合适的值。

<BigramTable />

```python
class BigramModel(nn.Module):
    def __init__(self, vocab_size):
        super().__init__()
        self.token_embedding = nn.Embedding(vocab_size, vocab_size)

    def forward(self, idx, targets=None):
        logits = self.token_embedding(idx)  # 查表
        if targets is not None:
            loss = F.cross_entropy(logits.view(-1, logits.size(-1)), targets.view(-1))
        return logits, loss
```

训练 5000 步，9 秒：

```text
step     0 | val loss 4.53  ← 随机猜（ln(65)=4.17，还没开始学）
step  2500 | val loss 2.82
step  5000 | val loss 2.53  ← 收敛了
```

生成效果：

```text
NG ce'ig yosthe th hoo, phey,
As wabel nd CKc! nos yo nor s,
```

能拼出 th、he、ng 这种常见的字母搭配，但凑不出完整的单词。一个字符的信息量就这么多，能学到这一步已经不错了。

## 模型 2：MLP，看前 16 个字符

Bigram 的问题很明显：一次只看 1 个字符。"t" 后面跟什么，得看前面是 "tha"（→ "t"）还是 "wri"（→ "t" → "e"），单看一个字符根本判断不了。

那就把窗口拉大，一次看前 16 个字符，把它们拼起来过一个全连接网络。

<MLPWindow />

```text
窗口 [B, e, f, o, r, e, ' ', w, e, ' ', p, r, o, c, e, e]
  → 每个字符查 embedding（64 维向量）
  → 16 个向量拼成 16×64 = 1024 维长向量
  → 两层全连接（1024 → 256 → 256 → 65）
  → 预测下一个字符
```

这就是 Bengio 在 2003 年提出的方法，是神经语言模型的雏形，二十多年过去仍然是教科书里的标准写法。

训练 10000 步，71 秒：

```text
step     0 | val loss 4.10
step  3000 | val loss 1.83
step 10000 | val loss 1.78  ← 比 Bigram 好了一个量级
```

生成效果：

```text
GLOUCESTER:
But that's all be a poisention'd to be itied.

CLIFFORD:
Has hees soney not have kind so thity where is you
```

这次能看到完整的单词了，"角色名 + 冒号"的格式也学会了。但句子经常读到一半就断掉，因为窗口固定只有 16 个字符，更远处的内容它看不到。

## 模型 3：MiniGPT，Self-Attention

MLP 还有几个问题：

1. 窗口固定，超过 16 个字符的内容看不到
2. 拼接的方式权重太多，窗口一大参数量就爆炸
3. 每个位置一视同仁，分不清哪些更重要

我们希望模型能自己决定"看哪里"，而不是一直死板地看前 N 个字符。

举个例子，要预测 `"the king said to his ___"` 的下一个词：

```text
the   king   said   to   his   ???
 ↑      ↑↑     ↑↑↑    ↑    ↑↑
低关注  高关注  最关注  低关注 高关注
```

直觉上，"said" 和 "king" 决定了下一个词是什么，"the" 和 "to" 几乎没有信息量。Attention 做的就是这件事：根据当前位置的需要，在历史里临时分配权重，重要的位置多看一点，不重要的就忽略。

<AttentionFlow />

具体怎么分配？做法是给每个位置发三样东西：Query 表示它当前在找什么，Key 表示它对外暴露的标签，Value 是它实际携带的信息。

计算的时候，当前位置拿自己的 Query，和历史里每个位置的 Key 一一做点积。点积大说明对方的内容正好对得上，权重就高；点积小则基本无关。把这些权重过一遍 softmax 归一，再去加权求和所有位置的 Value，就得到了当前位置的输出。

```text
当前位置的 Query 和所有历史位置的 Key 做点积
→ 点积大 = 匹配度高 = 注意力权重高
→ 按权重加权求和所有位置的 Value
→ 得到当前位置的输出
```

写成公式：

<Math block>{`\\text{Attention}(Q, K, V) = \\text{softmax}\\!\\left(\\frac{Q K^\\top}{\\sqrt{d_k}}\\right) V`}</Math>

公式里的 <Math>{`\\sqrt{d_k}`}</Math> 是用来缩放数值的。维度一大，点积也跟着变大，softmax 容易落到饱和区，梯度就传不回去了。

一个 Attention 只能学到一种关注模式，不太够用。语言里要照顾的关系很多，所以一般会并行开 4 个 Attention Head，各自学各自的，最后把结果拼起来。再叠上 FFN 做非线性变换、LayerNorm 稳住训练、残差连接防止梯度消失，就构成了一个 Transformer Block。把它堆 2 层，就是这里要训练的 MiniGPT：

```text
Token Embedding + Position Embedding
  → TransformerBlock × 2
    ├─ Multi-Head Attention（4 头，每头 32 维）
    └─ FFN（128 → 512 → 128）
  → LayerNorm
  → Linear → 预测下一个 token
```

总共 42 万参数，能看到 64 个字符的上下文。

训练 10000 步，110 秒：

```text
step     0 | val loss 3.97
step  3000 | val loss 1.71
step  7000 | val loss 1.60
step 10000 | val loss 1.58  ← 又往下降了一截
```

生成效果：

```text
WARWICK:
The bies is becan never he was are in my what pate.

CORIOLANUS:
The sight hear, for the an of I know
A power! When can our good:
But with a cillain.

KING EDWARD IV:
Your come bote yet for his true.
```

句子已经能读了。角色名拼写正确、冒号换行格式对、标点也大致到位，偶尔甚至能看到一点语义上的连贯。给它一个 prompt 也能接得下去：

```text
输入: "KING RICHARD:"
输出: "KING RICHARD:
       Why, bloody lies to advantage on your father.

       ROMEO:
       The state whitus of Rome, are his priests..."
```

它甚至自己续写了一段 ROMEO 的台词。

## 三个模型对比

| 模型 | 参数量 | 上下文 | Val Loss | 训练时间 | 效果 |
|------|--------|--------|----------|----------|------|
| Bigram | 4K | 看 1 个字符 | 2.53 | 9s | 字母组合，无单词 |
| MLP | 350K | 看 16 个字符 | 1.78 | 71s | 有单词，格式对 |
| MiniGPT | 420K | 看 64 个字符 | 1.58 | 110s | 句子通顺，能对话 |

<ModelComparison />

两次提升做的其实就两件事：

- Bigram → MLP：能看到的字符从 1 个变成 16 个，看到的更多
- MLP → MiniGPT：从平均看 16 个，变成自己挑哪几个该多看，看得更准

## 代码结构

```text
minimal-llm/src/
  prepare_data.py     # 下载 Shakespeare + 字符级 tokenize
  model.py            # BigramModel / MLPModel / MiniGPT
  train.py            # 训练（--model bigram/mlp/minigpt）
  generate.py         # 加载 checkpoint 交互式生成
  data/               # 训练数据
  checkpoints/        # 模型权重
```

运行：

```bash
python prepare_data.py                    # 下载数据
python train.py --model bigram            # 训练 Bigram（9秒）
python train.py --model mlp               # 训练 MLP（71秒）
python train.py --model minigpt           # 训练 MiniGPT（110秒）
python generate.py --model minigpt --prompt "KING RICHARD:"  # 生成
```

## 和工业界的距离

| 环节 | 这个项目 | GPT-4 级别 |
|------|---------|-----------|
| 模型 | 2 层 Transformer，42 万参数 | 上百层，万亿参数 |
| 上下文 | 64 个字符 | 128K token（约 50 万字符） |
| 训练数据 | 1MB 莎士比亚 | 几十 TB 互联网文本 |
| 训练时间 | 110 秒，单卡 Mac | 几个月，数千张 GPU |
| 词表 | 65 个字符 | 10 万子词（BPE） |
| 效果 | 能写像莎士比亚的句子 | 能写论文、写代码、做推理 |

骨架其实没什么差别，都是 Token Embedding + 若干层 Transformer Block + 输出头。差的全是规模。

下一篇会把字符级换成 BPE 子词。一个 token 不再只是单个字母，而是 "the"、"ing"、"tion" 这样有语义的片段，模型每跨一步能拿到的信息就多得多。
