# 从零搭一个语言模型

<SeriesNav series="llm" />

你打开 ChatGPT，输入"帮我写一首七言绝句"，两秒后它给你写了一首。你开始想：它怎么做到的？

拆开来看其实就一件事：给定前面的字，预测下一个字该是什么。"床前"之后大概率是"明月"，"明月"之后大概率是"光"。把这件事做到极致——看得更远、预测得更准——就是 GPT。

这篇从最简单的模型开始，逐步升级到能生成莎士比亚风格文本的 mini Transformer。三个模型，同一份数据，效果逐级提升。

---

## 语言模型在做什么

一句话：

```text
给定前面的 token，预测下一个 token 的概率分布。
P(next | context)
```

<NextTokenPrediction />

"token"可以是字符、子词、或整个词。这篇用最简单的字符级——每个字母/标点/换行就是一个 token。

Tiny Shakespeare 数据集有 65 个不同字符（大小写字母 + 标点 + 空格 + 换行），所以 `vocab_size = 65`。模型的任务就是：看到前面一串字符，预测第 66 种可能里哪个概率最高。

---

## 数据

用 Tiny Shakespeare——莎士比亚全集的一个子集，100 万字符，1MB。长这样：

```text
First Citizen:
Before we proceed any further, hear me speak.

All:
Speak, speak.

First Citizen:
You are all resolved rather to die than to famish?
```

角色名 + 冒号 + 台词 + 换行。格式固定，模型如果学得好，生成的文本也应该有这个格式。

数据准备：

```text
1. 扫一遍所有字符，排序编号 → 字符表（65 个字符）
2. 编码："Hello" → [20, 43, 50, 50, 53]
3. 切分：前 90% 训练，后 10% 验证
4. 保存为二进制文件（省内存、读取快）
```

---

## 模型 1：Bigram — 只看前一个字符

最简单的想法：只看当前字符，预测下一个。

```text
看到 'H' → 下一个大概率是 'e'（He/His/Her...）
看到 'q' → 下一个大概率是 'u'（qu- 组合）
看到 ':' → 下一个大概率是换行（台词开始）
```

实现上就是一张 65×65 的查找表。第 i 行表示"当前字符是 i 时，下一个字符的概率分布"。模型从数据里学这 4225 个数字。

<BigramTable />

```python
class BigramModel(nn.Module):
    def __init__(self, vocab_size):
        super().__init__()
        self.token_embedding = nn.Embedding(vocab_size, vocab_size)

    def forward(self, idx, targets=None):
        logits = self.token_embedding(idx)  # 查表
        if targets is not None:
            loss = F.cross_entropy(logits.view(-1, logits.size(-1)), targets.view(-1))
        return logits, loss
```

训练 5000 步，9 秒：

```text
step     0 | val loss 4.53  ← 随机猜（ln(65)=4.17，还没开始学）
step  2500 | val loss 2.82
step  5000 | val loss 2.53  ← 收敛了
```

生成效果：

```text
NG ce'ig yosthe th hoo, phey,
As wabel nd CKc! nos yo nor s,
```

能拼出常见字母组合（th、he、ng），但没有完整单词。因为只看一个字符，信息太少了。

## 模型 2：MLP — 看前 16 个字符

Bigram 的问题：只看 1 个字符，看不到上下文。"t" 后面跟什么取决于前面是 "tha"（→ "t"）还是 "wri"（→ "t" → "e"）。

解决：看前 16 个字符，全部拼起来过全连接网络。

<MLPWindow />

```text
窗口 [B, e, f, o, r, e, ' ', w, e, ' ', p, r, o, c, e, e]
  → 每个字符查 embedding（64 维向量）
  → 16 个向量拼成 16×64 = 1024 维长向量
  → 两层全连接（1024 → 256 → 256 → 65）
  → 预测下一个字符
```

这就是 Bengio 2003 年的方法——神经语言模型的开创性工作。

训练 10000 步，71 秒：

```text
step     0 | val loss 4.10
step  3000 | val loss 1.83
step 10000 | val loss 1.78  ← 比 Bigram 好了一个量级
```

生成效果：

```text
GLOUCESTER:
But that's all be a poisention'd to be itied.

CLIFFORD:
Has hees soney not have kind so thity where is you
```

有完整单词了，角色名 + 冒号的格式也学会了。但语法经常断裂——因为窗口固定 16 个字符，看不到更远的上下文。

## 模型 3：MiniGPT — Self-Attention

MLP 的问题：

1. 窗口固定，看不到 16 个字符以外的内容
2. 拼接方式权重太多，窗口大了参数爆炸
3. 所有位置权重相同，不管哪个字符更重要

**核心想法**：让模型自己决定"看哪里"，而不是固定看前 N 个。

举个例子。要预测 `"the king said to his ___"` 的下一个词：

```text
the   king   said   to   his   ???
 ↑      ↑↑     ↑↑↑    ↑    ↑↑
低关注  高关注  最关注  低关注 高关注
```

"said" 和 "king" 对预测下一个词更关键，"the" 和 "to" 没什么信息量。Attention 让模型根据当前位置的需要，动态分配对历史每个位置的关注程度。

<AttentionFlow />

**怎么实现这个"动态关注"？**

每个位置同时扮演两个角色：

- 当它需要信息时，发出一个 **Query**（"我在找什么？"）
- 当它被别人查看时，提供一个 **Key**（"我有什么？"）和一个 **Value**（"我的实际内容"）

匹配过程：

```text
当前位置的 Query 和所有历史位置的 Key 做点积
→ 点积大 = 匹配度高 = 注意力权重高
→ 按权重加权求和所有位置的 Value
→ 得到当前位置的输出
```

写成公式就一行：

```text
输出 = softmax(Q × K^T / √d) × V
```

除以 √d 是为了稳定数值（点积会随维度变大）。

**从 Attention 到完整模型**

单个 Attention 只能学一种"关注模式"。但语言理解需要同时关注多种东西（语法、语义、位置关系），所以用 4 个 Attention Head 并行，各学各的模式，最后拼起来。

加上 FFN（前馈网络做非线性变换）、LayerNorm（稳定训练）、残差连接（防止梯度消失），就是一个 Transformer Block。堆 2 层就是我们的 MiniGPT：

```text
Token Embedding + Position Embedding
  → TransformerBlock × 2
    ├─ Multi-Head Attention（4 头，每头 32 维）
    └─ FFN（128 → 512 → 128）
  → LayerNorm
  → Linear → 预测下一个 token
```

总共 42 万参数，能看 64 个字符的上下文。

训练 10000 步，110 秒：

```text
step     0 | val loss 3.97
step  3000 | val loss 1.71
step  7000 | val loss 1.60
step 10000 | val loss 1.58  ← 又好了一截
```

生成效果：

```text
WARWICK:
The bies is becan never he was are in my what pate.

CORIOLANUS:
The sight hear, for the an of I know
A power! When can our good:
But with a cillain.

KING EDWARD IV:
Your come bote yet for his true.
```

句子基本通顺了。角色名正确、冒号换行格式对、有标点、甚至有一些语义连贯性。给它一个 prompt：

```text
输入: "KING RICHARD:"
输出: "KING RICHARD:
       Why, bloody lies to advantage on your father.

       ROMEO:
       The state whitus of Rome, are his priests..."
```

能续写多个角色的对话了。

## 三个模型对比

| 模型 | 参数量 | 上下文 | Val Loss | 训练时间 | 效果 |
|------|--------|--------|----------|----------|------|
| Bigram | 4K | 看 1 个字符 | 2.53 | 9s | 字母组合，无单词 |
| MLP | 350K | 看 16 个字符 | 1.78 | 71s | 有单词，格式对 |
| MiniGPT | 420K | 看 64 个字符 | 1.58 | 110s | 句子通顺，能对话 |

<ModelComparison />

每一步提升的核心原因：

- Bigram → MLP：**看更多上下文**（1 → 16），知道"前面是什么"
- MLP → MiniGPT：**动态决定看哪里**（固定权重 → attention），知道"什么更重要"

## 代码结构

```text
minimal-llm/src/
  prepare_data.py     # 下载 Shakespeare + 字符级 tokenize
  model.py            # BigramModel / MLPModel / MiniGPT
  train.py            # 训练（--model bigram/mlp/minigpt）
  generate.py         # 加载 checkpoint 交互式生成
  data/               # 训练数据
  checkpoints/        # 模型权重
```

运行：

```bash
python prepare_data.py                    # 下载数据
python train.py --model bigram            # 训练 Bigram（9秒）
python train.py --model mlp               # 训练 MLP（71秒）
python train.py --model minigpt           # 训练 MiniGPT（110秒）
python generate.py --model minigpt --prompt "KING RICHARD:"  # 生成
```

## 和工业界的距离

| 环节 | 这个项目 | GPT-4 级别 |
|------|---------|-----------|
| 模型 | 2 层 Transformer，42 万参数 | 上百层，万亿参数 |
| 上下文 | 64 个字符 | 128K token（约 50 万字符） |
| 训练数据 | 1MB 莎士比亚 | 几十 TB 互联网文本 |
| 训练时间 | 110 秒，单卡 Mac | 几个月，数千张 GPU |
| 词表 | 65 个字符 | 10 万子词（BPE） |
| 效果 | 能写像莎士比亚的句子 | 能写论文、写代码、做推理 |

结构完全相同——都是 Token Embedding + Transformer Blocks + LM Head。区别只在规模。

下一篇把字符级词表换成 BPE 子词——一个"token"不再是单个字母，而是 "the"、"ing"、"tion" 这样的片段。同样的模型，同样的训练方式，但每一步能看到更多信息。
