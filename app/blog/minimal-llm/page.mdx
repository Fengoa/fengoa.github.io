# 从零搭建一个语言模型

<SeriesNav series="llm" />

在 ChatGPT 里输入"帮我写一首七言绝句"，两秒钟后就收到了一首完整的诗。这到底是怎么做到的？

核心其实很简单：给定前面的字，预测下一个字。"床前"后面大概率是"明月"，"明月"后面大概率是"光"。一个模型把这件事预测得足够准，它就是 GPT。

<NextTokenPrediction />

这篇文章从最简单的模型开始，逐步构建到能够生成莎士比亚风格台词的 mini Transformer。共包含三个模型，均使用相同的数据集。


## 语言模型的定义

将这一过程形式化，仅需一行数学表达：

<Math block>{`P(\\text{next} \\mid \\text{context})`}</Math>

给定一段前文，模型输出下一个 token 在词表上的概率分布。token 的粒度可以灵活设定，可以是单个字母，也可以是 "ing" 这样的片段，或者一个完整的词。本文采用最简单的字符级方案，每个字母、标点和换行均视为一个 token，整个词表仅包含 65 个字符。

模型的目标是学习这一分布。前文越长，分布估计越准确，生成的文本也就越通顺。

---

文本转换为 token 的方法是：为 65 个字符分别编号（0 到 64），按照该映射表对文本进行编码。`"Hello"` 被转换为 `[20, 43, 50, 50, 53]`，此后模型仅处理整数序列。

## 数据

本文使用 [Tiny Shakespeare](https://raw.githubusercontent.com/karpathy/char-rnn/master/data/tinyshakespeare/input.txt) 数据集，该数据集从莎士比亚全集中截取，大小为 1MB，约含 100 万字符。整个文件仅包含 65 种不同字符，包括大小写字母、常见标点、空格和换行——前文提到的 `vocab_size = 65` 即源于此。

数据片段大概长这样：

```text
First Citizen:
Before we proceed any further, hear me speak.

All:
Speak, speak.

First Citizen:
You are all resolved rather to die than to famish?
```

文本通篇采用"角色名 + 冒号 + 台词"的格式，结构规整。若模型训练充分，生成的文本应呈现相同格式。

将整个文件按照前述字符表进行 tokenize，得到一长串整数序列。其中前 90% 用于训练，后 10% 留作验证。最终数据存为二进制文件，以加快后续加载速度。


## 模型 1：Bigram，仅观察前一字符

最简单的方案是仅根据当前字符预测下一字符，例如：

```text
看到 'H' → 下一字符大概率为 'e'（He/His/Her...）
看到 'q' → 下一字符大概率为 'u'（qu- 组合）
看到 ':' → 下一字符大概率为换行（台词开始）
```

实现上仅需一张 65×65 的查找表，第 i 行存储"当前字符为 i 时，下一字符的概率分布"。模型的任务是调整这 4225 个参数至合适的值。

<BigramTable />

PyTorch 实现如下：

```python
class BigramModel(nn.Module):
    def __init__(self, vocab_size):
        super().__init__()
        self.token_embedding = nn.Embedding(vocab_size, vocab_size)

    def forward(self, idx, targets=None):
        logits = self.token_embedding(idx)  # 查表
        if targets is not None:
            loss = F.cross_entropy(logits.view(-1, logits.size(-1)), targets.view(-1))
        return logits, loss
```

在 Mac 上训练 5000 步耗时约 9 秒，loss 迅速收敛：

```text
step     0 | val loss 4.53  ← 随机猜测（ln(65)=4.17，还没开始学）
step   500 | val loss 3.41
step  1000 | val loss 3.02
step  2000 | val loss 2.86
step  2500 | val loss 2.82
step  3500 | val loss 2.65
step  4500 | val loss 2.56
step  5000 | val loss 2.53  ← 收敛了
```

训练完成后，让模型生成一段文本，结果如下：

```text
NG ce'ig yosthe th hoo, phey,
As wabel nd CKc! nos yo nor s,
```

模型能够生成 th、he、ng 等常见字母组合，但无法构成完整单词。单一字符提供的信息有限，能达到此效果已属合理。


## 模型 2：MLP，观察前 16 个字符

Bigram 的局限性在于：仅观察单个字符。"t" 后的后续字符取决于前文是 "tha" 还是 "wri"，仅凭单个字符无法准确判断。

为此，扩大观察窗口至前 16 个字符，将其拼接后输入全连接网络。

<MLPWindow />

处理流程如下：

```text
窗口 [B, e, f, o, r, e, ' ', w, e, ' ', p, r, o, c, e, e]
  → 每个字符查询 embedding（64 维向量）
  → 16 个向量拼接为 16×64 = 1024 维向量
  → 两层全连接（1024 → 256 → 256 → 65）
  → 预测下一个字符
```

该方法由 Bengio 等人于 2003 年提出，是神经语言模型的奠基性工作，至今仍是教科书中的标准范式。

训练 10000 步耗时 71 秒，loss 较 Bigram 降低一个数量级：

```text
step     0 | val loss 4.10
step  1000 | val loss 2.42
step  2000 | val loss 1.96
step  3000 | val loss 1.83
step  5000 | val loss 1.81
step  7500 | val loss 1.79
step 10000 | val loss 1.78
```

生成的文本质量较上一模型显著提升：

```text
GLOUCESTER:
But that's all be a poisention'd to be itied.

CLIFFORD:
Has hees soney not have kind so thity where is you
```

模型已能生成完整单词，并习得"角色名 + 冒号"的格式。但句子常在中途断裂，原因在于窗口固定为 16 个字符，无法获取更远的上下文信息。


## 模型 3：MiniGPT，Self-Attention

扩大 MLP 观察窗口的直接方法是增大窗口尺寸。但 MLP 将窗口内所有字符的 embedding 拼接为长向量后输入全连接层，若窗口从 16 扩至 1024，第一层参数量将增长 64 倍，计算代价过高。

此外，MLP 对窗口内每个位置施加相同的权重，与具体内容无关。预测 `said to his ___` 的下一词时，真正相关的实为 `said` 和 `his`，但 MLP 无法区分，对所有位置均采用同一组权重处理。

理想情况下，模型应根据当前输入自行决定需要重点关注哪些位置。

以预测 `"the king said to his ___"` 的下一词为例，各历史位置的重要性大致如下：

<AttentionExample />

直觉上，"said" 和 "king" 决定下一词的内容，"the" 和 "to" 提供的信息量极少。Attention 机制的功能即在于此：根据当前位置的需求，在历史中动态分配权重，对重要位置给予更多关注，忽略不重要位置。

<AttentionFlow />

注意力权重的分配机制如下：为每个位置生成三组向量：Query 表示当前位置的查询需求，Key 表示位置的索引标签，Value 是位置携带的实际信息。

计算时，当前位置使用其 Query 与历史各位置的 Key 逐一计算点积。点积越大表明匹配度越高，对应权重越高；点积较小则基本无关。将这些权重通过 softmax 归一化，再对全体位置的 Value 进行加权求和，即得当前位置的输出。整个流程可概括为：

```text
当前位置的 Query 和所有历史位置的 Key 做点积
→ 点积大 = 匹配度高 = 注意力权重高
→ 按权重加权求和所有位置的 Value
→ 得到当前位置的输出
```

公式表达仅需一行：

<Math block>{`\\text{Attention}(Q, K, V) = \\text{softmax}\\!\\left(\\frac{Q K^\\top}{\\sqrt{d_k}}\\right) V`}</Math>

公式中的 <Math>{`\\sqrt{d_k}`}</Math> 用于缩放点积结果。维度较高时点积值易过大，导致 softmax 落入饱和区，梯度难以回传。

---

单一 Attention 仅能学习一种关注模式，表达能力有限。语言中存在多种需同时处理的关系，因此通常并行设置 4 个 Attention Head，各自独立学习，最终拼接输出结果。在此基础上叠加 FFN 进行非线性变换、LayerNorm 稳定训练、残差连接缓解梯度消失问题，即构成一个 Transformer Block。堆叠 2 层该 Block，并在前后分别添加 embedding 层和输出层，即得到本文训练的 MiniGPT：

```text
Token Embedding + Position Embedding
  → TransformerBlock × 2
    ├─ Multi-Head Attention（4 头，每头 32 维）
    └─ FFN（128 → 512 → 128）
  → LayerNorm
  → Linear → 预测下一个 token
```

模型总计 42 万参数，上下文窗口为 64 个字符。

训练 10000 步耗时 110 秒，loss 进一步下降：

```text
step     0 | val loss 3.97
step  1000 | val loss 2.18
step  3000 | val loss 1.71
step  5000 | val loss 1.65
step  7000 | val loss 1.60
step 10000 | val loss 1.58
```

此次生成的文本已具备可读性：

```text
WARWICK:
The bies is becan never he was are in my what pate.

CORIOLANUS:
The sight hear, for the an of I know
A power! When can our good:
But with a cillain.

KING EDWARD IV:
Your come bote yet for his true.
```

角色名拼写正确，冒号换行格式符合规范，标点基本准确，偶尔可见语义上的连贯性。给定 prompt 后模型能够续写，例如输入 "KING RICHARD:"，模型可生成整段对话：

```text
输入: "KING RICHARD:"
输出: "KING RICHARD:
       Why, bloody lies to advantage on your father.

       ROMEO:
       The state whitus of Rome, are his priests..."
```

模型甚至自主生成了 ROMEO 的台词。


## 三个模型对比

| 模型 | 参数量 | 上下文 | Val Loss | 训练时间 | 效果 |
|------|--------|--------|----------|----------|------|
| Bigram | 4K | 观察 1 个字符 | 2.53 | 9s | 字母组合，无单词 |
| MLP | 350K | 观察 16 个字符 | 1.78 | 71s | 有单词，格式对 |
| MiniGPT | 420K | 观察 64 个字符 | 1.58 | 110s | 句子通顺，能对话 |

<ModelComparison />

两次改进的核心在于：

1. Bigram → MLP：观察范围从 1 个字符扩展至 16 个字符，获取更多信息
2. MLP → MiniGPT：从均匀观察 16 个字符，演进为自适应选择关键位置，提升观察准确性
