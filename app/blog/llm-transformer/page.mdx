# 搭一个完整的 Transformer

<SeriesNav series="llm" />

上一篇讲完了 self-attention，但只有 attention 训不出像样的模型。把 attention 单独拎出来跑，loss 会一直在高位徘徊。真正在 GPT-2 里发挥作用的是一整个 Transformer block：LayerNorm 把数值压住，attention 决定看谁，残差给信息留一条不被覆盖的通道，FFN 再把刚看到的内容揉一遍。

判断一个组件到底重不重要，最直接的办法是把它拿掉看看会发生什么。同样的 2 层、128 维、4 头、64 上下文配置，分别去掉一个组件训 3000 步：

<AblationBarChart />

四个组件去掉一个，loss 都会上升 0.2 以上，去掉 LayerNorm 最严重，直接退化到 2.25。后面分别讲清楚每个组件填的是什么坑。

## 一个 block 内部的数据流

先把整体走一遍，再去看具体的零件。一个 Transformer block 内部，输入 `x` 会过两遍“先 norm 再做事再加回原值”的循环：第一遍是 attention，第二遍是 FFN。

<TransformerBlockFlow />

写成代码就是这样：

```python
def block_forward(x):
    x = x + attn(layer_norm_1(x))   # 第一遍：look around
    x = x + ffn(layer_norm_2(x))    # 第二遍：digest
    return x
```

这种 “先 norm 再算” 叫 Pre-Norm，是 GPT-2 之后的事实标准。原始论文的 Post-Norm 把 norm 放在残差相加之后（`layer_norm(x + attn(x))`），训练更不稳定，深一点就经常崩。

## LayerNorm：把数值幅度压回正常区间

LayerNorm 是这次消融实验里去掉影响最大的一个。它的计算极其简单——把每个位置的向量减去自身均值，再除以标准差：

<Math block>{`\\text{LN}(x) = \\frac{x - \\mu}{\\sqrt{\\sigma^2 + \\epsilon}} \\odot \\gamma + \\beta`}</Math>

`γ` 和 `β` 是两个可学习参数，给模型留一点重新调整尺度的余地。但归一化才是核心操作。

为什么要这么做？看一下不归一化时分布是怎么走的：

<LayerNormEffect />

把上一层 scale 拖到 5，分布一下子摊到 ±15 这种区间。送进 attention 之前不做处理的话，QK 点积就会变成几十几百级别，softmax 直接饱和，梯度回不来。LayerNorm 之后所有向量都被压成均值 0、方差 1，下游几乎感受不到上一层 scale 的扰动。

实现就一行：

```python
def layer_norm(x):
    return (x - x.mean(-1, keepdim=True)) / (x.std(-1, keepdim=True) + 1e-5)
```

工业界的常见替代是 RMSNorm，省掉减均值那一步，速度更快，效果几乎一样。

## 残差连接：给信息和梯度一条直达通道

去掉残差，loss 会涨 0.33。整个 block 写成式子是这样：

<Math block>{`x_{l+1} = x_l + \\text{Sublayer}(\\text{LayerNorm}(x_l))`}</Math>

这个加号不止是数值上的“加回去”，它从两个方向起作用。

向前看，每一层都是在原始信息基础上做增量修改。哪怕这一层 attention 什么也没学到，输出接近 0，原信号至少不会丢。这意味着堆 100 层的时候，第 1 层的 token embedding 仍然有可能直接出现在第 100 层的输出里，模型不必从头“重建”每次输入。

向后看，反向传播的链式法则需要乘穿每一层的雅可比矩阵。如果中间某一层激活值很小，梯度就会被压扁成接近 0。残差相当于在主干上挂了一条恒等映射，梯度可以沿着这条 `x` 的路径不经过非线性变换直接传回去。深度模型能堆几十上百层，靠的就是这条直达通道。

## FFN：每个位置自己再消化一次

去掉 FFN 影响最小（loss +0.21），但去掉之后模型的表达能力会塌缩——它只剩下加权混合，没有非线性的“处理”能力。

FFN 长这样：两层全连接，中间维度扩大 4 倍，再压回来。

<FFNExpansion />

为什么要先扩到 512 再缩回 128？高维度有更多“工作空间”，可以暂存复杂的中间表示。如果一直在 128 维里打转，能编码的状态有限。Transformer Feed-Forward Layers Are Key-Value Memories 那篇论文用电路视角去看，发现 FFN 第一层的每个神经元都对应一个特定的输入模式（key），第二层把对应的内容（value）写回。换句话说，模型大部分“事实知识”就存在 FFN 的权重里。Attention 决定去哪个书架取书，FFN 是那个书架。

代码就是 PyTorch 一个 `nn.Sequential`：

```python
self.net = nn.Sequential(
    nn.Linear(n_embd, 4 * n_embd),  # 升维
    nn.GELU(),                       # 非线性
    nn.Linear(4 * n_embd, n_embd),  # 降回
)
```

GELU 比 ReLU 平滑，负值不会一刀切到 0。后来 LLaMA 把这套换成了 SwiGLU——多一个 gate，参数量略增，效果更好，现在新的开源模型基本都用它。

## 位置编码：告诉模型谁前谁后

self-attention 本身完全不关心顺序。`Q · K` 是点积，对调两个 token 不会改变结果。这对语言是灾难——“cat sat on mat” 和 “mat sat on cat” 含义完全相反。

最简单的办法是给每个位置一个可学习的向量，加到 token embedding 上：

```python
tok_emb = self.token_embedding(idx)
pos_emb = self.position_embedding(pos)
x = tok_emb + pos_emb
```

模型于是同时拿到了两件事：这是什么 token、它在第几个位置。位置不同，下游 attention 看到的 Q/K 就不一样，输出也就不一样。

这种学到的绝对位置编码是 GPT-2 的做法，缺点是位置数量训练时就锁死了——ctx=64 的模型遇到第 65 个 token 时直接没编码可用。后面那篇关于 RoPE 的文章会讲怎么把位置信息揉进 Q/K 内部，让模型可以外推到训练时没见过的长度。

## 整个 GPT-2 风格模型长什么样

把所有零件装回去，一个完整的 decoder-only LLM 的骨架就是：

```python
x = token_embedding(idx) + position_embedding(pos)  # 进入主干
for block in self.blocks:                            # N 个 Transformer block
    x = block(x)
x = layer_norm_final(x)                              # 收尾再 norm 一次
logits = lm_head(x)                                  # 投影到 vocab，预测下一个 token
```

模型参数都长在哪？把 MiniGPT 的 42 万参数按模块拆开看：

<ParamBreakdownPie />

切到 GPT-2 Small 会发现有意思的事：尺寸差了三百倍，每个模块的占比却几乎不变。FFN 大约一半，attention 占四分之一，embedding 加起来占大头。GPT-4 估计是同样的比例继续往上拉。模型“做大”这件事，其实是把每个模块都按比例放大，结构本身不变。

## 和工业界的距离

| 环节 | 这个项目 | 大模型 |
|------|---------|-----------|
| 层数 | 2 | 100+ |
| 维度 | 128 | 8000+ |
| 参数量 | 42 万 | 万亿 |
| Norm | Pre-LayerNorm | RMSNorm |
| FFN | GELU | SwiGLU |
| 位置编码 | 学到的绝对位置 | RoPE |
| Attention | 标准多头 | Grouped-Query Attention |

骨架完全一致，工业界的工作集中在替换零件：RMSNorm 比 LayerNorm 算得快、SwiGLU 比 GELU 表达力强一点、RoPE 解决长度外推、GQA 省 KV cache 显存。每一个改动都是单点优化，不动整体结构。
